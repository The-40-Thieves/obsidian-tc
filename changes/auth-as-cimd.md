- **The bundled authorization server now resolves Client ID Metadata Documents (CIMD), and advertises `client_id_metadata_document_supported: true`.** A `client_id` that is an `https://` URL with a path is fetched through the same bounded fetch OIDC discovery uses (https only, no redirects, every resolved address public and the connection pinned to it, 5 KiB, 5 s; there is no private-network opt-in for a document, and `logo_uri`, `jwks_uri` and `client_uri` are never fetched), validated (the document's `client_id` must equal the URL, `redirect_uris` must hold an https or loopback URI) and cached for its `Cache-Control: max-age` clamped to 5 minutes to 24 hours (errors are never cached, only the validated fields are kept, and the table is capped). The client-authentication method is read from `token_endpoint_auth_methods_supported` and the singular `token_endpoint_auth_method` only when the list is absent, so ChatGPT's document (singular `private_key_jwt`, list `["private_key_jwt", "none"]`) resolves to `none` and completes the flow, while a document that permits only `private_key_jwt` is refused. Such a client is bound to `none`: a secret, a Basic header or a `client_assertion` at `/oauth/token` or `/oauth/revoke` is `invalid_client` (this now applies to static public clients too), and a document that cannot be fetched at the token endpoint is `503 temporarily_unavailable` rather than `invalid_client`. `auth.as.cimd.allowedHosts` now takes effect. The consent page names the host the client is registered at and warns when the operator has never approved a metadata-document client; the loopback-redirect warning follows the redirect actually requested (any `127.0.0.0/8` address, `::1` or `localhost`, http or https). Authorize, consent, token and revocation all look a client up through one resolver. See the auth model. A sign-in that returns to a loopback address stays remembered across ports once the client is approved (the default, so Claude Code and Codex sign in without a click); the new `auth.as.consent.loopback: prompt` shows the consent page on every such sign-in instead, because nothing proves which local process is behind a port (see the auth model for the trade-off). Metadata-document lookups are bounded by one deadline that covers the name lookup (OIDC and JWKS fetches share it), a per-source budget of five uncached lookups a minute with at most two running at once (an IPv6 address counts as its /64, and a peer with no usable address, such as a same-host proxy or tunnel, shares one smaller bucket instead of being exempt), and a check of the request itself before any fetch; the authorize page no longer says why a client could not be used, consent re-checks the client when it is approved, and the client's name is shown without control, format or bidirectional characters.

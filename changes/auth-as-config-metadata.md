- **An opt-in bundled authorization server: configuration, discovery metadata, its own signing key and store (no sign-in routes yet).** A new `auth.as` block (off by default, so nothing changes unless `auth.as.enabled` is set) is validated at load: it needs `auth.mode: jwt`, `auth.resource` and an `issuer` that is a bare https origin (`http` only for loopback), refuses `auth.tokenTtlSeconds` below `accessTokenSeconds`, an `auth.authorizationServers` list that does not lead with the issuer, a `jwksUri` pointing at the server's own key set, and duplicate client ids. With it enabled the HTTP transport serves RFC 8414 metadata at `/.well-known/oauth-authorization-server` (and the OpenID discovery alias), built only from the configured issuer and never from the request's `Host`: PKCE `S256`, the RFC 9207 `iss` parameter, `client_id_metadata_document_supported` with `none` as a client-authentication method, and no `registration_endpoint` unless `auth.as.dynamicRegistration` is turned on (it is off by default). Protected Resource Metadata names the issuer first by default. At server start the server generates its own `as` signing key once (idempotent, never in a lost registry, never replacing a key of another algorithm), opens a new `<cacheDir>/oauth.db` (its own migration chain; losing it is fail-safe, but back it up with `auth.db` and `auth-keys/`) and deletes expired rows from it at boot and on every maintenance sweep (`oauth_rows_reaped`). A configured `auth.jwks` or `auth.jwksFile` holding the `as` key's public key refuses the boot; a remote `auth.jwksUri` cannot be checked. `doctor` gains an `auth.as` check (issuer, metadata URL, claimed or unclaimed, key id, algorithm and age, DCR state, settings, and a backup reminder), and `doctor` now reports each registry key's purpose correctly in `auth.registry`. Token verification is tightened: an `as` token needs a string `sub`, `jti` and `client_id` and a numeric `iat`, only fully qualified scopes count, and on every path a `jti` that is present but not a string is refused instead of being read as absent (which made such a token impossible to revoke). See the auth model and `auth.as` in the config reference.

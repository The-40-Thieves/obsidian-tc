---
type: Changed
config-schema-change: auth.as.dynamicRegistration
---
- **Dynamic Client Registration (RFC 7591) in the bundled authorization server is now on by default (`auth.as.dynamicRegistration` defaults to `true`).** Many MCP surfaces (Meta Muse Code, Antigravity, Cursor, grok.com, Grok Build, Mistral Le Chat, n8n, the Gemini app and Windsurf) can only register through DCR, so a server with the bundled authorization server enabled now works with them out of the box: the metadata advertises `registration_endpoint` and `POST /oauth/register` is served. The abuse controls from the DCR release still bound it (`auth.as.dcr.perIpPerHour`, `maxClients`, `unusedDays`; unused registrations are deleted, and only a successful sign-in counts as use). Behind a same-host proxy or tunnel every client shares one per-source bucket until a trusted-proxy setting exists. To turn it off, set `auth.as.dynamicRegistration: false`: `/oauth/register` is then a 404 and `registration_endpoint` is not advertised. `securityProfile: "hardened"` still forces it off, now including when the flag is unset (an explicit `true` there is still ignored with a notice). The boot message changes from a warning to one info line naming the limits and how to disable it. Nothing changes for servers that have not enabled `auth.as`.

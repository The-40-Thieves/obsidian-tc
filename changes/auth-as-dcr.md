- **The bundled authorization server can now register clients by Dynamic Client Registration (RFC 7591), behind `auth.as.dynamicRegistration` (off by default).** Claude.ai and ChatGPT custom connectors and some other clients (Gemini CLI, Cursor) still ask for a `registration_endpoint`; with the flag on, `POST /oauth/register` takes a JSON registration and answers `201` with a server-chosen `client_id`. Registered clients are public (`token_endpoint_auth_method` must be `none` or absent, so `client_secret_basic`, `client_secret_post` and `private_key_jwt` are refused with `invalid_client_metadata`, and no secret is ever issued), `redirect_uris` must be https or loopback with a private-use scheme such as `cursor://...` dropped rather than refused while one usable URI remains, and `grant_types` and `response_types` must be ones the server serves. A `client_id` in the request is ignored, so a registration cannot take a static client's id or a metadata-document URL; every other member is ignored and never fetched. Registered clients resolve through the same client resolver as static and metadata-document clients, so authorize, consent, token and revocation treat them alike, and their consent page warns that the application registered itself and has never been approved (and, as for any client, nothing is remembered until the operator approves). The surface is bounded: `auth.as.dcr.perIpPerHour` registrations per source (the TCP peer; an IPv6 address counts as its /64; peers behind a same-host proxy or tunnel share one bucket; no forwarded header is read) answer `429` with `Retry-After`, `auth.as.dcr.maxClients` rows answer `503` (a full table first drops registrations never used within a day), and a registration unused for `auth.as.dcr.unusedDays` is deleted by housekeeping. A warning is logged at boot while DCR is on, the metadata advertises `registration_endpoint` only then, and `securityProfile: "hardened"` forces DCR off even when the flag is set (the loader says so). The three `dcr` keys and the flag already existed in the schema and `doctor` output; only the `dynamicRegistration` description changed.

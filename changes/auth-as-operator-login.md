- **Operator login for the bundled authorization server (still no authorize or token route).** With `auth.as.enabled`, the server now has one operator account in `<cacheDir>/oauth.db`: until it is claimed, `/oauth/login`, `/oauth/authorize`, `/oauth/token` and `/oauth/register` answer `503` "not claimed". Claim it with the new `obsidian-tc auth as set-password [--user <name>] [--stdin]` (asks twice with no echo, or reads one line from stdin; run again it changes the password and ends the account's sessions), or on a host with no shell at `/oauth/setup` with the one-time token held in the environment variable named by `auth.as.setupTokenEnv` (at least 24 characters, single use, valid for 24 hours after the server starts, never logged). Two claims at once have exactly one winner. Passwords are at least 12 characters and stored as Argon2id through `node:crypto.argon2` at the OWASP minimum parameters (rehashed at login when the parameters are raised); a Node older than 24.7 refuses to start the server with `auth.as.enabled`, naming the version it needs, and the rest of the server is unaffected. `/oauth/login` and `/oauth/logout` use a `__Host-otc_as` session cookie (`HttpOnly; Secure; SameSite=Lax`; the un-prefixed name without `Secure` only on a loopback http issuer), a server-side session store that keeps only a SHA-256 of the id, a new id at every login, 30-minute idle and 12-hour absolute expiry, per-account and per-address brute-force limits with exponential backoff (an unknown name behaves like a wrong password), form tokens plus an `Origin` check on every form, 303 after every POST, and a strict Content-Security-Policy with `frame-ancestors 'none'` and `X-Frame-Options: DENY` on every page. Nothing is advertised yet: discovery metadata still appears only once the authorize and token routes exist. See the auth model.

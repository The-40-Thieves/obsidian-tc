- **Auth residuals closed.** `securityProfile: "hardened"` now sets `auth.requireJti: true`, so the hardened posture refuses a jti-less bearer on every path (HS256, JWKS, OIDC, `/metrics`) with `jti_required`; an explicit `auth.requireJti: false` still wins and the schema default stays `false`, planned to flip to `true` at the next major release. `auth.algorithms` is now one allowlist for every verify surface: `["EdDSA"]` refuses HS256 (configured secret and registry keys) on the MCP edge and on `/metrics`, where it was previously never consulted. `/.well-known/jwks.json` caps `Cache-Control: max-age` at the seconds left until the earliest `retire_after` among the published keys (`no-cache` when under a second) and adds an `ETag` with `304` support, so a downstream cache cannot keep a retiring key past the point this server stops verifying it. The auth-rejection log line now says "token has NOT expired; it exceeded auth.tokenTtlSeconds" only for `token_max_age`, not for every rejection of an unexpired token.

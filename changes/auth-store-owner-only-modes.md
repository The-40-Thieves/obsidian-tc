- **The authorization server's databases are owner-only, and a looser copy from an earlier version is tightened on upgrade.** `auth.db` and `oauth.db`, with their `-wal` and `-shm` files, are created 0600. A file an earlier version left readable by group or other is chmodded to 0600 before it is opened, and the server writes one line to stderr naming it. A file that cannot be tightened (a symbolic link, a hard link, another user's file, or a chmod error such as `EPERM`) is left as it is, and that line says why; the database still opens, and nothing refuses to start. The line names files by basename only. This is POSIX only: on Windows there is no owner-only mode, so protect `<cacheDir>` with its ACL. A signing-key file readable by others is still refused rather than tightened, because it may already have been read.

- **`commit_wiki_page` no longer reports an error for a write that landed, validates the stamp it adds, and documents its real undo.** Snapshot retention and reindexing after the batch are best-effort: a fault there (`SQLITE_BUSY`, say) is logged and returned as a `post_commit` problem instead of failing a call whose page and patches are already on disk, so "all or nothing on errors" holds for the errors that can still undo anything. With the provenance frontmatter stamp on, the new page's final frontmatter, stamp included, is checked against `SCHEMA.md` (a property vocabulary that does not declare the stamp key gets a `schema` problem); the stamp docs now list `commit_wiki_page`. A new page has no prior state and so no snapshot: `restore_note` undoes the patches and overwrites a commit makes, and a new page is removed with `delete_note`; the earlier claim that `restore_note` undoes page creation was wrong and is corrected. The `acl.rules[].scopes` schema description no longer says rule scopes do not filter search and listing results (they do).

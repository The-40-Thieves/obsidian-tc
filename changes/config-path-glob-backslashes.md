---
type: Security
config-schema-change: egress.excludePaths, acl.rules, acl.readPaths, acl.writePaths, acl.deletePaths, vaults.index.excludePaths, vaults.acl.rules, vaults.acl.readPaths, vaults.acl.writePaths, vaults.acl.deletePaths
---
- **Backslash path globs no longer silently match nothing.** A vault path is always forward-slash, but a config glob was only Unicode-normalised, so `Private\**` (the natural Windows spelling) compiled to a pattern no path could match. For the `readPaths` / `writePaths` / `deletePaths` whitelists that failed closed, but for restrictions it failed open: `egress.excludePaths: ["Private\\**"]` still sent those notes to the embedding provider and judge, and an `acl.rules` glob such as `notes\private\**` required no scope. Every operator path glob (`acl.rules[].glob`, the three `*Paths` whitelists at the root and per vault, `egress.excludePaths`, and path-prefix entries of `vaults[].index.excludePaths`) is now normalised once at config load: a backslash is a separator and repeated separators collapse. A vault path cannot contain a backslash, so there is no escape use to preserve; a `/regex/` index exclusion is left as written. `obsidian-tc doctor` gains `config.path-globs`, which warns about a configured glob that matches no file in its vault, with stronger wording for restrictions that fail open.
- **Breaking: an ACL pattern anchored at a root is refused at load.** An ACL glob is matched against a vault-relative path with no leading separator, so `acl.rules[].glob`, `readPaths`, `writePaths` or `deletePaths` (root or per vault) written `/Private/**`, `\Private\**`, `C:\notes\**`, a UNC `\\server\share`, or `./Private/**`, or ending in a separator (`notes\private\`), could never match a note: for a rule the extra scopes were silently bypassed. Config load now rejects these with the vault-relative spelling to use (`Private/**`, `notes/private/**`) instead of stripping the marker, which could have turned an inert whitelist entry into a grant. A config that carries one now fails to start (`serve` and `obsidian-tc doctor` both print the field and the fix); those rules never worked, so rewrite them vault-relative. Egress and index patterns keep their strip and widen behaviour. `config.path-globs` also reports an index exclusion that is empty or an invalid regex, and no longer calls a dead ACL rule with no scopes fail-open.
- **Breaking: an ACL pattern with a `.` or `..` segment, or a control character, is refused at load.** Runtime paths reject `..` and drop `.`, so `../Private/**`, `Private/./**` and `Private/../**` never matched the folder they named and the rule's extra scopes were bypassed; they now fail config load with a hint to spell the folder itself (`Private/**`). A control character (NUL, tab, newline, DEL, C1) is refused too: NUL is the matcher's internal `**` marker and over-matched. Names that merely contain dots (`.obsidian/**`, `a..b/**`) still load. Refused, not normalised, so a security pattern is never silently rewritten.
- **`obsidian-tc setup` no longer rewrites a config it cannot read.** Following the startup error's advice with `setup --force` used to drop the parsed config and rebuild from defaults, replacing a restrictive `acl`, `auth` and `egress` with permissive ones. The same happened to a file that was malformed JSON (read as "no config") or whose JSON root was not an object (`null`, `123`, `"x"`, `false`, which crashed the loader with a TypeError that setup then swallowed). `setup` (with `--force`, `--yes` or `--dry-run`) now prints the problem (each offending field, the JSON parse error with its line and column where the runtime reports one, or the root type), exits 1 and leaves the file untouched; fix it by hand, then re-run. A new `--replace-invalid-config` flag, never implied by `--force`, replaces such a file on purpose: it makes a backup first and prints that the old `acl`, `auth` and `egress` settings are discarded. A missing config is still created on first run, and a config that merely lacks an explicit `cacheDir` or embeddings choice (the case `setup` exists to repair) is still merged and rewritten with its `auth`/`acl` kept. The loader itself now raises a typed `config root must be an object` error instead of a TypeError.

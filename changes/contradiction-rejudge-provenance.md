- **Contradiction flags written by the old judge can now be re-judged, and every judge call records the model that actually answered.** A 100-pair audit of stored contradiction rows found the original judge over-flagged: two independent frontier labelers called about 94% of the flagged sample `no_conflict`, and the stored verdict matched them on 3 of 86. The gateway's `judge` alias has since been repointed at a far more accurate model, but rows stored the alias itself, so old and new verdicts were indistinguishable. The gateway client now resolves LiteLLM's `x-litellm-model-id` header through `/model/info` to the real `provider/model` string (LiteLLM echoes only the requested alias in the response body), so `judge_model` and the synthesis/challenge/citation attestations carry the resolved model; if the lookup fails the call still succeeds and falls back to the reported name. The new `obsidian-tc contradiction-rejudge [--dry-run]` command re-runs the judge, with the detector's exact request shape, over open flags: a row the judge now calls `no_conflict` is dismissed with a recorded reason (original verdict kept, never deleted), a still-flagged row has its verdict, rationale and model updated, and every ruling stamps `rejudged_at`. It is rate-limited (`--concurrency`, `--delay-ms`), resume-safe (a row is ruled on at most once), skips rows whose chunks changed or sit under `egress.excludePaths`, and `--dry-run` prints counts with zero gateway calls and zero writes. Every consumer (`list_contradictions`, `vault_context`, `knowledge_challenge`, the advisory sweep, consolidation) already read only open rows, so dismissed rows drop out of all of them. Adds migration `20261001_001`, which adds `rejudged_at` and `resolution_reason` to `contradictions`; back up `cache.db` before the first run.

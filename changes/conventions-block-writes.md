- **Vault conventions: a `severity: block` rule refuses a write that adds its violation.** A write whose note would gain a blocking folder-convention violation (a required property missing, or a value outside its allowed list) fails with `convention_blocked` before any byte reaches disk. A refused write takes no snapshot, trashes nothing, spends no confirmation and releases its idempotency key, so a corrected retry runs. A write that only fixes a note, or edits a note that already broke the rule, is never refused, and a `warn` rule still only warns. Note names are matched case-insensitively, so `.MD` is a note too. Restores, cross-note backlink rewrites, and moves and copies (the destination of each) stay warn-only: `copy_note` now reports the same `conventions` field as `move_note`.

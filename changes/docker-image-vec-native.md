- **The Docker image loads `sqlite-vec` and the native module again.** In 1.32.0 the image booted with `native=js-fallback vec=off`, so dense retrieval silently fell back to the brute-force cosine scan (and the vault I/O and scoring to the pure-JS paths). The image used to rely on Bun's runtime auto-install to fetch both packages, which Bun switches off as soon as a `node_modules` directory exists; 1.32.0 added one for the Redis rate-limit backend. The image now installs `sqlite-vec` (with the platform package for its architecture, linux/amd64 and linux/arm64) and the compiled `obsidian-tc-native` module at build time, so both load with no network and no runtime install. `ci-docker` now boots the built image with `--network none` and fails unless the ready banner reports `native=on vec=on`, and the image build fails if the native prebuild is missing (`--build-arg NATIVE_REQUIRED=0` accepts the pure-JS fallback for local builds). Existing deployments get dense retrieval back by pulling the new image; no config change is needed. Both release routes (`publish.yml` and the `release-image` recovery dispatch) now push the image to a staging tag, boot linux/amd64 and linux/arm64 of that exact digest offline, and only then promote the same digest to the public tags; `release-image` builds from the `v<version>` tag and verifies the npm-delivered native binaries against the release's Sigstore bundles.

- **`doctor --probe` checks the public URL hosted MCP clients use, and a deploy recipe for them.** With `auth.resource` set to a public host, `obsidian-tc doctor --probe` now reports `public-url.dns` (an IPv4 A record: Anthropic's outbound range is IPv4-only, so an AAAA-only host fails), `public-url.tls` (a publicly trusted certificate, with a warning inside 14 days of expiry), `public-url.challenge` (an unauthenticated `POST` gets `401` with `resource_metadata`), `public-url.prm` (the PRM `resource` equals the URL and names an authorization server), `public-url.as-metadata` (the authorization server's metadata is served with a matching `issuer`; the server, authorization and token domains Gemini Enterprise's egress allowlist needs are listed) and `public-url.redirects` (no response redirects to another host). Each verdict names the section of the new hosted-clients deployment page that fixes it: per-surface requirements for claude.ai, ChatGPT, Gemini Enterprise, the Gemini app, grok.com, Le Chat, Copilot Studio and the API connectors, plus cloudflared, nginx (`proxy_buffering off`, `proxy_http_version 1.1`, read timeouts, `X-Accel-Buffering`) and Caddy (`flush_interval -1`) recipes. Without `--probe`, or when `auth.resource` is unset or a loopback or private host, one `public-url` check is skipped and nothing is requested. The probe never follows a redirect and refuses any non-https or non-public host it reads from the remote documents. An unbuffered-SSE probe is not part of this check.

- **An in-band approval of a destructive call now completes when the call acts on a vault other than the session's own, and the session trace keeps that call.** The confirmation prompt's signed request state was sealed with the session's vault, so approving a call that acted on a different vault (an explicit `vault`, or the single visible vault when the first one is hidden) was refused at redemption and the call never ran; it is now sealed with the vault the call acts on, and a state sealed for one vault still authorizes no other. A declined prompt stays a hard stop. The confirmation telemetry rows (offered, answered) carry that same vault, so they pair with the call's episode. The session JSONL trace used to drop such a call; it now records it in the session's own file with `effect_vault` naming the vault it acted on, and `obsidian-tc rerun` reports those records as `refused_by_policy` (a re-run is bound to the session's vault) instead of a divergence.

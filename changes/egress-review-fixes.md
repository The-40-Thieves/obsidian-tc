- **Egress review fixes.** An `https://` provider request that answers with a redirect is now refused: the ordinary fetch followed a 307/308 and replayed the POST body (the bearer key and vault text) to a `Location` that never met the destination policy, so every provider client (gateway, TypeSafe, embeddings, reranker, bridge) now sends `redirect: "manual"` and fails on any 3xx with a `Location`, nothing sent to it. The IPv6 cloud-metadata addresses inside `fc00::/7` (`fd00:ec2::254` on AWS, `fd00:64:64:64::254` on Alibaba, `fd20:ce::254` on GCP) and Alibaba's `100.100.100.200` inside the CGNAT range are refused, listed or not; one list (`isCloudMetadataAddress`) now backs the provider policy, the config literal check and the OIDC address check. `server_health` `deprecations` no longer name hosts or vault ids to an anonymous or vault-bound caller (they get one generic line with the count; a caller that may read every vault still gets the detail), and its advice now comes from the same DNS-backed classification as `doctor`: only a host resolving solely to private addresses is told to be listed, a tailnet/CGNAT host is told to be listed only if it is a tailnet peer, and a public or metadata host is told it is refused and to use `https://` (it used to claim they work). OIDC discovery and JWKS fetches now connect to the addresses they validated instead of resolving the name a second time (closing the DNS-rebinding window), with TLS still verified against the issuer hostname; as a result `HTTPS_PROXY` is not used for the identity provider unless `auth.oidc.allowPrivateNetwork` is set. The OIDC address check also blocks 6to4 (`2002::/16`) and Teredo (`2001:0::/32`) addresses that embed a blocked IPv4, and `allowedJwksHosts` now admits a hostname on the default https port only. A `jwks_uri` is shown as its origin only (no path, query string or userinfo, in the message or the error cause) in startup logs, errors and `doctor`. `doctor` now FAILS `auth.registry` for an `auth.db` that exists but cannot be opened (it reported OK while `serve` aborted), and a caller's abort now cancels a provider client's retry backoff (and the gateway `rerank` and the post-completion `/model/info` lookup) instead of leaving a `Retry-After` sleep and its timer behind. Provider timeouts now cover the response body, not only the headers (an endpoint answering `200` and then stalling is cut off at the timeout, socket closed; a body is capped at 32 MiB), and an `https://` URL naming a cloud-metadata literal such as `https://169.254.169.254/` is refused. The configuration descriptions and the plain-http release note now state that a listed host may also resolve into the tailnet/CGNAT range `100.64.0.0/10`.

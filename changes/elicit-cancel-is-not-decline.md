- **A cancelled approval prompt is no longer reported as a refusal.** An MCP elicitation `cancel` means the prompt was dismissed without a choice, but it was being rendered as "The user declined this change. Do not retry it and do not mint a token." while the error's recovery text said to mint a token, so a headless client (Claude Code run non-interactively auto-answers `cancel` within milliseconds) obeyed the text and could never complete a cross-folder `move_note`, `delete_note` or `write_note` overwrite, even when the operator had approved and the model had a shell. `cancel` now still refuses the write (it is never an approval) but reports `approval_not_obtained` and gives the `obsidian-tc elicit --hash <args_hash> --tool <name>` route in both the message and `recovery`; an explicit `decline` stays a hard stop (`approval_declined`, do not retry, do not mint). One shared mapping covers every gated tool. Stale "Claude Code has no elicitation" comments, usage text and docs were corrected.

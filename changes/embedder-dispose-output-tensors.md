- **The local embedder and reranker now release each request's tensor instead of leaving it for the garbage collector, so a long-lived server no longer keeps a burst's peak memory for its whole life.** `embed()` copied its vectors out with `tolist()` and returned without calling `dispose()`, leaving the tensor's native ONNX Runtime buffer alive until Bun's garbage collector next ran — and that collector is driven by JS heap pressure while this garbage is almost entirely native, so it ran late. Reported in #1433 against a 2,277-note vault on a 12 GB host: the process reached 2.37 GB after 15 hours with a 2.9 GB peak and never gave it back while idle, and forcing a collection every 5 seconds cut the resident swing by 262 MB and the peak by 177 MB — evidence that the memory was collectable garbage rather than a leak. `packages/embedder-local` and `packages/reranker-local` now dispose in a `finally`, freeing the buffer per request including on the path where the vector-count check throws. Batch-size defaults, a post-burst collection and a recyclable embedder process remain open in that issue.

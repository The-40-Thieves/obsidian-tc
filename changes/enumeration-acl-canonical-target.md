- **Listings and scans of a symlinked folder are filtered by what it points at, not by its name.** With `wiki -> private` and `readPaths: ["wiki/**"]`, `read_note wiki/secret-project.md` was refused (it resolves to `private/secret-project.md`) while `list_notes` named the file with its size and mtime, because the walkers emitted the lexical `wiki/...` name and every consumer filtered on it. Each walked entry now carries the symlink-resolved `aclRel` next to its display path, computed the way the ACL resolves a path, and every consumer that filters walker output (`list_notes`, `list_tags`, `find_notes_by_tag`, `list_properties`, `find_notes_by_property`, `list_attachments`, `list_kanban_boards`, `query_canvas`, `query_base`, `list_tasks`, `bundle_folder`, OCR selection, `search_text`, `search_regex`, `search_jsonlogic`, the link and graph scans, resource listing, `index_vault` candidates) decides on `aclRel` through one shared filter, `readableEntry`. Paths the caller names (`query_canvas`/`list_tasks` `paths`, `list_periodic_notes`) are resolved first by `readableResolved`. A readable target still lists under its display path. An unconfigured symlink behaves as before (native still refuses to read it).

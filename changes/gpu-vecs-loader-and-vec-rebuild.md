- **Loading vectors computed off-box could report success while writing nothing, leave the dense index nearly empty, or trip the single-active constraint (GH #1161).** `eval/load-gpu-vecs.ts` addressed `chunk_embeddings.model` as `${provider}:${model}`, which is not `provider.id` for the `local` embedder (`local:nomic-embed-text-v1.5:fp32`), so it updated zero rows and said so as a success; it now asks the provider for the id and treats zero rows written as an error. `--insert` upserts and retires the chunk's other-model rows before activating the new one, which the unique active index requires. `ensureVecChunks` now rebuilds `vec_chunks` from `chunk_embeddings` in full when the table is missing over active vectors (rebuild reason `table_missing`): it used to re-create it empty and fill it one chunk at a time, so dropping the table left 390 of 16,882 rows with no error. A new `invalidateVecIndex` helper in `search/vec.ts` marks the index stale without writing a sentinel fingerprint; the three eval loaders that dropped the table use it.

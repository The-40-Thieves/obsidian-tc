- **The HITL confirmation round trip now works in every HTTP auth mode, and is no longer keyed from `auth.jwtSecret`.** The 2026-07-28 `inputRequired`/`requestState` codec was only built when `auth.jwtSecret` was set, so under `auth.mode: oidc` and an asymmetric-only `jwt` deployment (a JWKS or registry keys, no secret) a destructive call got the plain `elicit_required` error and a generic client could not complete it; and rotating `jwtSecret` silently voided every pending confirmation. The codec key is now derived (HKDF, its own label) from the per-server secret `<cacheDir>/server-secrets/wiki-generated.key`, the file that already seals generated wiki pages (created on first use, `0600`, its name and the wiki seals unchanged). Servers sharing a `cacheDir` accept each other's confirmations. **On upgrade, a confirmation that was pending is refused once and the client is offered a fresh one** (a confirmation lives 300 s by default); there is no dual-key verify. `server-secrets/` joins `auth-keys/` as state to back up: deleting it voids pending confirmations and regenerates the wiki pages. Removing `auth.jwtSecret` no longer affects the round trip, only `read_notes` cursors.

- **`OBSIDIAN_TC_DEFAULT_VAULT` now decides the server's default vault everywhere, not only in the vault registry.** An HTTP or OAuth caller with no vault binding (no `vault` claim, no grant vault) was pinned to the first vault listed in `vaults`, so the variable named a vault such a caller could not reach. It now follows the default. Because an HTTP caller is bound to exactly one vault, a caller that used to work in the first vault is moved to the default after upgrading, and a call that names the old vault answers `forbidden`: if a client must stay on a specific vault, give its token a vault (`token mint --vault`), bound the account, or pick a persona at consent. The same default now also applies to the stdio caller's vault (so `resources.boundVaultOnly: true` confines it to the default vault, as the config docs say), to the vault the `tc.server.start`, `tc.server.shutdown` and `tc.maintenance.sweep` MORGIANA events are attributed to (their spool moves to `<cacheDir>/<default>/`), and to the Prometheus `vault` label on calls that name no vault. With the variable unset, or naming an unknown vault, the first vault is used exactly as before.

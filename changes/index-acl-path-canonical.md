- **Search and the other index-backed tools authorize a stored note by what it is, not by the name it was indexed under.** The search index keyed a note by the path it was walked under, and every DB-backed result was authorized on that name. Through a symlinked folder the two differ: with `wiki -> private`, a principal allowed `wiki/**` and denied `private/**` was handed `wiki/secret-project.md` by `search_semantic`, `search_text`, `vault_graph_search`, `knowledge_search`, `reflect`, `vault_context`, `list_contradictions` and the tag, property and graph tools (while `read_note` refused it). The mirror case failed closed wrongly: with `shared -> pages` and only `pages/**` readable, an indexed, readable note was rejected under its `shared/...` name. Migration `20261009_001` adds `chunks.acl_path` and `notes.acl_path`, the symlink-resolved path computed the way the ACL resolves a path; the indexer writes it with every row (including index-on-write) and re-syncs it on every pass without re-embedding, and every stored-row reader decides on it through one shared resolver. A row with no resolved identity (every row that predates the migration until the next `index_vault` or reconcile pass, or a writer that supplied none) is returned to nobody rather than trusted; the identity of the permitted-path set cache moved with it, so no set built from names is reused. The index also matches `read_note` on two more refusals: a hard-linked note (`st_nlink > 1`, which realpath cannot see through) is never indexed and any row an earlier pass stored for it is closed, and a pass no longer aborts on one; a symlink into `.obsidian`, `.git` or `.trash` is still not indexed. After upgrading, results reappear as the first pass resolves each note.

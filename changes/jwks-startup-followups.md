- **JWT-mode key-set follow-ups.** A `auth.jwksUri` that answers `200` with something that is not a key set (not JSON, no `keys` array) or that times out inside jose is now rejected as `idp_unavailable` instead of `malformed`, so diagnostics and the rejection metric name the real cause (the token was already refused either way). A stdio-only boot (no HTTP, no `/metrics`) now prints the missing-audience deprecation too; it never built a verifier, so it said nothing. The startup `auth.jwksUri` line says `could not verify the key set at startup; will retry on each request` when the lookup times out or fails, and keeps `REFUSED` for a definitive policy refusal, since the fetch decides again on every request. `auth.resource` alone (without `auth.authorizationServers`) is still accepted by the config schema while the verifier binds no audience from it; that is now documented in the auth model and pinned by a test, and the two will be aligned in the next minor release, when the missing-audience deprecation becomes an error.

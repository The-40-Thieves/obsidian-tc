type: Security
---
- **JWT-mode `auth.jwksUri` is now pinned to the validated address.** The remote key set was fetched by jose's own fetch, which resolved the name a second time (a DNS-rebinding window) and read the body with no size cap. It now goes through the same checked transport as OIDC discovery: the host is resolved once and the connection goes to those addresses (SNI and certificate on the hostname), redirects are refused, the body is capped at 256 KiB. The default is `https://` on a public host. A loopback host needs no entry; a host listed in `network.plainHttpHosts` may be `http://` or on a private/tailnet address (the same rules as a provider URL); link-local and cloud metadata addresses are refused even when listed, as is plain `http://` to a public host. An unlisted host that resolves only to private addresses keeps working for one release with a deprecation (startup line, `obsidian-tc doctor` `auth.jwks-uri`, `server_health`): list it in `network.plainHttpHosts`. A refused or failed key-set fetch now logs as `idp_unavailable`. The startup line and `doctor` say which mode is active.
- **A JWKS key source with no effective audience is deprecated.** `auth.resource` binds the token audience only when Protected Resource Metadata is complete (`auth.authorizationServers` too), so a `resource`-only config with `jwks`, `jwksFile` or `jwksUri` accepted tokens its issuer minted for another service, with a stderr line at most (none for `jwksUri`). It now warns at startup, in `obsidian-tc doctor` (`auth.jwks-audience`) and in `server_health`, and becomes a startup error in the next minor release. Set `auth.audience`, or `auth.allowMissingAudience: true` to opt out. A configured audience is enforced as before.
- **`auth.mode: jwt` with only `auth.jwksUri` as its key source now builds a verifier.** The boot check skipped `jwksUri`, so such a config reported "no verifier" instead of verifying against the remote key set.

---
type: Changed
config-schema-change: embeddings.maxBatchTokens, embeddings.concurrency
---
- **The local embedder now gets its own batching defaults: `embeddings.maxBatchTokens` resolves to 512 and `embeddings.concurrency` to 1 under `provider: "local"`, while every other provider keeps 2048 and 4.** Both numbers were sized for a remote runner — keeping a batch inside Ollama's `n_ctx` 4096 — but they also decide how large each in-process ONNX inference is and how many run at once. As reported in #1433, measured resident memory scales with chunks per request (one chunk is about 0.5 GB, four about 1.1 GB, thirty-two about 1.9-2.7 GB for nomic q8), and one long-lived server settled at 1.5 GB with a 2.9 GB peak. A value you set explicitly still wins, per key, including one that happens to equal what the provider would have resolved. The trade is reindex throughput: `concurrency: 1` leaves a many-core host under-used during a full reindex, so raise it explicitly when the host has memory to spare. Steady-state edits arrive as small batches and barely change.

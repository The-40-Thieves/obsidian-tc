- **Memory writes honor the folder write ACL with `materialize: false` too.** `create_entity` checked the write ACL on the entity's projection path (`<memory folder>/<type>/<name>.md`) only when materializing, so a caller holding `write:memory` but no write access to that folder could still create the row by passing `materialize: false`. The check now runs in both modes, right after the read check and before any collision lookup, so an existing and an absent entity in an unwritable folder return the identical `acl_denied` and no row is created. The same gap is closed in `add_observation`, `link_entities`, `unlink_entities`, `rename_entity` (write on the new path, delete on the old one when the name changes) and `delete_entity` (delete), through one shared helper. Unrestricted and default-ACL configs are unchanged; a vault with a restricted `writePaths`/`deletePaths` must list the memory folder for these tools to keep working on unmaterialized entities.

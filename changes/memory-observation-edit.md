- **`update_observation` corrects or retires a memory observation by id, no key needed.** Observations made by `create_entity` have no key, and `add_observation` supersedes only by key, so a wrong fact could only be contradicted by appending another (0/3 on the write-ergonomics `memory-observation` task). Every observation now has a stable `observation_id` (`obs_<n>`, derived from its existing interval row, so observations written before this release are addressable with no migration), returned by `create_entity` (an `observations` list), `add_observation` and both `get_entity` formats and `query_entity_graph`. `update_observation { entity_id, observation_id, observation }` replaces the text, `{ …, retire: true }` removes it with nothing in its place. Nothing is hard-deleted: the old text is closed (`valid_to` set, `superseded_by` names the replacement), hidden from default reads, still visible with an earlier `as_of` and under the note's Superseded section; a correction keeps the old observation's key, so key supersession keeps working. It needs `write:memory` plus write access to the entity's note path in both materialize modes, an unreadable entity reads as `entity not found`, and the new text goes through `memoryDefense` like any other memory write. `create_entity`, `add_observation` and `get_entity` descriptions now point at it.

- **Memory reads now honor the folder read ACL.** `get_entity` and `query_entity_graph` returned any memory entity to a caller holding `read:memory`, even when `readPaths` (or `strictReadDefault`) hides the entity's own note, which renders the same observations and `[[links]]`. An entity is now readable only when `read_note` could read its note (`<memory folder>/<type>/<name>.md`, computed from the current name, so `materialize: false` and renamed entities are gated too). An unreadable entity is reported exactly like a nonexistent one (same error, left out of by-name ambiguity, relations to it omitted), `query_entity_graph` never walks through one (pages and cursors are computed after filtering), and the write and lifecycle tools that look an entity up (`add_observation`, `link_entities`, `unlink_entities`, `rename_entity`, `delete_entity`) answer an unreadable entity with the same not-found as a missing one, so they cannot be used to probe for it. **Breaking for a restricted `readPaths`:** memory under a folder your `readPaths` does not list is now hidden from that caller; add `memory/**` (or your configured `memory.folder`) to `readPaths`. Default configs (no `readPaths`) are unchanged, and `obsidian-tc doctor --probe` has a new `memory.read-acl` check that warns when existing entities are hidden. The same gate closes the side channels around it: `create_entity` and `rename_entity` need read access to the path they claim before reporting a name collision (an unreadable target is `acl_denied` whether or not a row exists); `delete_entity` and `rename_entity` count, list and fingerprint only the relations `get_entity` shows, so a hidden edge changes no response, count or `state_fp`; an ownership conflict never names an owner the caller cannot read; and a memory type or name of `.` or `..` is rejected (an existing row with such a path fails closed). Relations stay written into the readable entity's own note as `[[links]]`, so a reader of that note sees linked entities' names (documented in SECURITY.md). `obsidian-tc doctor --probe` now also counts a stale stored location.

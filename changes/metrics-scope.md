type: Security
---
- **`/metrics` now requires an `admin:metrics` bearer under `auth.mode: jwt` or `oidc`, on every bind including loopback.** A scrape verified the bearer but discarded its scopes and vault binding, so any verified token, even one with no scopes bound to a single vault, could read process-wide gauges and counters for every vault (for example another vault's capture-queue depth). And a loopback bind was served with no token at all, which a Cloudflare Tunnel, Tailscale Serve, SSH reverse forward or reverse proxy to `127.0.0.1` turned into an open endpoint for remote callers. The endpoint now answers `401` for a missing or unverifiable token, `403` with `WWW-Authenticate: Bearer error="insufficient_scope"` for a verified token without `admin:metrics` (the scope `get_metrics` already requires; `*` and `admin:*` satisfy it), and `403` for a token bound to a vault or persona, since the series are process-wide and cannot be filtered per vault exactly. The token is checked by the same verifier instance the MCP HTTP transport uses (built once at boot), so `auth.jwks`, `jwksFile`, `jwksUri`, the audience and the algorithm list apply to `/metrics` too; a valid JWKS-signed token that was wrongly `401` is now accepted. A loopback listener also rejects a `Host` header that is not loopback, the bind host or in `transports.http.allowedHosts` (`403`, the MCP route's DNS-rebinding guard); `auth.mode: none` on a loopback bind stays open. Breaking for existing scrapers under `jwt` / `oidc`, including a local one on loopback: mint a scrape token with `obsidian-tc token mint --sub prometheus --scopes admin:metrics` (no `--vault`) and send it as a bearer; a tunnel or reverse proxy in front of `/metrics` needs the same token, and its public host name must be added to `transports.http.allowedHosts`.

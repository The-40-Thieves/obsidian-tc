- **A symlinked `wiki.folder` or `wiki.rawFolder` reads again with the native module loaded.** The native safe-open refuses a symlink in any path component, so with the compiled addon (every shipped install) `read_note` on `wiki/log.md` with `wiki -> pages` was refused as `acl_denied` ("refusing symlinked or missing path component"), while the pure-JS fallback served it. The vault registry now records the folders the operator configured, and the one native boundary in `vault/notes-io.ts` hands the native open the real directory of exactly those folders (resolved at the call and required to sit inside the vault). The native no-symlink rule is unchanged for everything else: a symlink planted elsewhere in the vault, under the real directory, as a file, or a configured folder that leads out of the vault is still refused. CI now runs the wiki, symlink and safe-open test files with the native addon loaded, so the two backends cannot drift apart unseen.

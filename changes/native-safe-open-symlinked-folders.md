- **A symlinked `wiki.folder` or `wiki.rawFolder` reads again with the native module loaded, and a retargeted symlink can no longer split the ACL from the I/O.** The native safe-open refuses a symlink in any path component, so with the compiled addon (every shipped install) `read_note` on `wiki/log.md` with `wiki -> pages` was refused as `acl_denied` ("refusing symlinked or missing path component"), while the pure-JS fallback served it. The vault registry now pins each configured folder that is a symlink to its real in-vault directory once, when the registry is built (a vault whose root is missing then is pinned by the first request through the folder, once). The native open takes the pinned directory without reading the symlink again, and the ACL refuses a path under a pinned folder whose symlink no longer leads to the pinned directory, so the ACL and the file actually opened or moved are always the same, even if the symlink is retargeted mid-request. Two vault ids that share one root but configure different wiki or raw folders are now refused at startup (and `add_vault` refuses a root that a wiki vault already uses), because a registry's pins are keyed by path. Each pin also records the real directory's identity, and the native open checks it on the directory it actually opened, so renaming another folder (the immutable raw folder, say) into the pinned name between the ACL and the I/O is refused too. The pins belong to the vault registry that placed them, so a second registry in the same process (a `session_rerun` sandbox) cannot replace them. A raw folder whose vault root was missing at startup is not pinned when the root appears (its real directory never got the immutable rule): while it is a symlink every path under it is refused with an error asking for a restart, and a wiki folder placed then that leads into the raw folder is refused the same way. The native no-symlink rule is unchanged for everything else: a symlink planted elsewhere in the vault, under the pinned directory, as a file, or a configured folder that leads out of the vault is still refused. CI now runs the wiki, symlink and safe-open test files with the native addon loaded, so the two backends cannot drift apart unseen.

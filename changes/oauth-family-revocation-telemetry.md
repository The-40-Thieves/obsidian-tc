- **OAuth family revocations are now observable.** A replayed authorization code or refresh token revokes its whole grant family on sight (RFC 9700 section 4.14) — correct behaviour, but it was visible only on the server's stderr, so a leaked credential acting as a one-request kill switch on a client's session left no queryable trace. Every family revocation now increments `reliquary_tc_auth_family_revocations_total{reason}` and writes a content-free `auth_family_revoked` row to cache.db's event log (when, which client id, which reason, how many access tokens died — never a code, token or hash), and `reliquary-tc doctor --probe` reports the last 24 hours as the `auth.family-revocations` check, warning on reuse-driven revocations. Revocation behaviour is unchanged. See GitHub issue 1477.

- **`patch_note` and `append_note` now say how to restructure a note, and a heading anchor can pick the Nth duplicate.** A write-ergonomics eval found that Claude Code could not move a section or edit under the second of two identical headings (0 of 3 runs on each) while Codex did both in one `replace_text` call anchored on the note's top-level heading; the gap was the tool description, not a missing operation. The `patch_note` description and its `anchor`, `old_string` and `new_string` fields now carry worked examples (add under a heading, move or reorder sections with one `replace_text` on an enclosing heading, `append_note` for the end of a note). A heading anchor takes `occurrence` (1-based, document order) or a `"Parent > Child"` path in `heading`; a heading that matches more than once without either was already refused rather than bound to the first match, and that refusal now lists every match line and names both fixes, while an out-of-range `occurrence` is refused with the lines that do exist. `read_note`'s section anchor accepts the same shapes. The `note_exists` refusal of `write_note` and `bulk_create_notes` said "use overwrite or upsert", which clients read as an `overwrite: true` flag and sent as an unrecognized key; it now names `mode: "overwrite"` / `mode: "upsert"` (and the missing-note refusal names `mode: "create"`), `write_note`'s `mode` field describes its values, and "either anchor or target_heading is required" shows each accepted anchor shape and points to `append_note` for end-of-note appends.

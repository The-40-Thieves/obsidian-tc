type: Security
---
- Filesystem detection uses an exclusive, UUID-named probe so an existing file at the probe name is never overwritten or deleted.
- **Folder-ACL glob matching no longer runs a regex engine against tool-call paths.** Each `**` compiled to `.*`, which backtracked catastrophically on a non-matching path, so a config with several `**` segments plus a crafted path could hang the server (regex DoS). Globs are now tokenized once and matched by a linear O(glob × path) dynamic program with identical semantics (`**` spans `/`, `*` and `?` do not, escapes unchanged); the regex form is kept only as the test oracle. `audit_provenance` include/exclude globs and the plane egress filter share the same matcher.
- **Folder ACLs now follow the vault's own filesystem case behavior instead of the process platform, directory by directory.** The platform default (`win32`/`darwin` fold) decided case-insensitive matching for every vault, so a vault on a case-sensitive APFS volume under macOS failed open both ways: a case-variant path satisfied a `readPaths` whitelist it never matched, and a case-variant folder escaped a rule's scope requirement. The mirror image held for a case-insensitive mount under Linux. NTFS and ext4 casefold also set case sensitivity per directory, so one answer for the vault root is not enough. Exact-case matches are unchanged. When only a case-insensitive match fits, the ACL asks the directories that path passes through: where they all fold, the folded match applies; where they all distinguish case, it does not; where they are mixed, missing or unreadable, the restrictive side wins (a rule's scopes are the union of both matches, an immutable glob applies, a whitelist does not match). Each vault root is still probed at startup (it is used for the vault identity key and wiki classification). The new `vaults[].caseSensitive` key overrides the probe: `true` means names differing only by case are different files, `false` means they are the same file, the same sense as APFS (Case-sensitive), NTFS `setCaseSensitiveInfo` and Samba's `case sensitive`. `RELIQUARY_TC_VAULT_CASE_SENSITIVE` overrides it for a single-vault config. The ACL fingerprint carries the case behavior and a new predicate version, so cached path sets built under the old matching are rebuilt. A `vault_identity` row recorded under the platform-default fold is upgraded in place when the vault's own filesystem folds differently, instead of refusing to boot. `reliquary-tc doctor` reports the resolution per vault (`vaults.case-sensitivity`) and warns while a vault root cannot be probed. No action needed unless doctor warns.

- Filesystem detection uses an exclusive, UUID-named probe so an existing file at the probe name is never overwritten or deleted.
- **Folder ACLs now follow each vault's own filesystem case behavior instead of the process platform.** The platform default (`win32`/`darwin` fold) decided case-insensitive matching for every vault, so a vault on a case-sensitive APFS volume under macOS failed open both ways: a case-variant path satisfied a `readPaths` whitelist it never matched, and a case-variant folder escaped a rule's scope requirement — and the mirror image held for a case-insensitive mount under Linux. Each vault root is now probed at startup (new `vaults[].caseSensitive` key overrides the probe; `OBSIDIAN_TC_VAULT_CASE_SENSITIVE` overrides it for a single-vault config), its ACL is compiled and fingerprinted with that fact, and an unprobeable root fails closed: whitelists match case-sensitively while rule scopes and immutable globs fold, so a wrong guess can only deny, never grant. `obsidian-tc doctor` reports the resolution per vault (`vaults.case-sensitivity`) and warns while any vault runs on the fail-closed split. No action needed unless doctor warns.

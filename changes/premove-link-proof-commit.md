- **A move's backlink rewrite is bound to what it was planned from, and commits as one batch.** `move_note`, `bulk_move_notes` and `move_attachment` now write the moved note and every backlink rewrite as a single write batch: each linking note is replaced only if it still holds the bytes the plan was made from, and a write error or a concurrent edit rolls the whole batch back, the move included. A note edited, or a new backlink added, between the plan and the commit re-plans and re-proves once, then refuses with `concurrent_modification` and nothing moved. `bulk_move_notes` commits the plan it proved instead of recomputing it after the files moved, so it can no longer fail with `invalid_input` after a file has moved. memoryDefense `block` mode now refuses in the plan, before anything moves, and each rewritten note's pre-image is snapshotted so `restore_note` can undo it. A refusal never names a note the caller cannot read (it counts them), and an unrepresentable link in an immutable raw note is skipped and reported instead of refusing the move. A bulk overwrite of the only other note with that name no longer falls back to a path link.

type: Security

- **A valid token with no `sub` can no longer share per-caller state with other such tokens, and one caller can no longer replay another's idempotency key.** A token that verifies but carries no `sub` authenticates as a caller with no identity, and three paths treated `null` as one shared identity: work memory (`work_episodes`, `work_search` and `work_forget` bound `caller IS NULL`, so one sub-less credential could read and tombstone another's episodes), sessions (`start_session` stored a NULL principal and `end_session` let any caller close such a session and append to its trace), and idempotency (a claim was keyed on the vault and key alone, so a second caller, identified or not, reusing a key with identical arguments got the first caller's cached result, `session_id` and `trace_path` included). Tools that keep per-caller state now declare `principalOwned` and dispatch refuses them for a caller with no identity with `forbidden` (reason `no_identity`): `work_episodes`, `work_episode_chain`, `work_search`, `work_forget`, `work_result`, `record_retrieval_feedback`, `explain_answer`, `start_session`, `end_session`, plus `vault_context` with `include_work`. A call with an `idempotency_key` from such a caller is refused too, and the key is now namespaced by the calling principal (migration `20261010_001` rebuilds `idempotency_keys` with `principal` in its primary key and drops its rows, since none recorded an owner: a keyed call retried within the replay window of the upgrade runs once more instead of replaying). `end_session` on a session with no recorded principal now needs `admin:workspace`. Nothing is derived from the token (`jti`, hash): that identity would change at every renewal and silently orphan the holder's memory. Add a `sub` to the token, or under `oidc` map `claimMapping.subject` or `principal` to a claim your provider sets. `token mint` requires `--sub`, the bundled authorization server always sets one, and stdio and `auth.mode: none` have fixed callers, so only a token minted elsewhere is affected; every other tool still serves a sub-less token. See the auth model docs.

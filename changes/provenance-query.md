- **`get_provenance`: the signed write history of one note.** Returns the provenance records that touched a path, newest first (`vault`, `path`, `limit`, `cursor`, `since`/`until` in epoch milliseconds, `include_verification`, `response_format`). Each record carries the tool, outcome, timestamp, sha256 before and after, and the attribution in three groups that are never mixed: `verified` (what the server established), `unauthenticated` (a label nobody proved) and `self_reported` (what the client claimed). A note moved with `move_note`, `bulk_move_notes` or `move_attachment` keeps the history of its earlier paths, followed backwards. `include_verification` re-checks each returned record's hash, signature and chain link with the same code as `obsidian-tc provenance verify`. The tool needs `read:provenance` in addition to `read:notes` (records name other principals and sessions), applies the vault's own folder ACL, answers an unreadable path exactly like a path with no history (`not_found`), and never lists a path of a multi-path record that the caller cannot read. A call is one bounded pass over the chain (`provenance.query.maxScanRows`, default 100000; `scan_truncated` when it ran out), a move is followed only if its record verifies (`lineage_incomplete` says why it stopped), `signature: "valid"` needs the body to still match its hash, a record with a hidden path returns a view hash instead of the stored one, and `cursor` is an opaque signed cursor bound to the request.

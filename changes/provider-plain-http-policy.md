- **Every outbound provider client now follows the plain-http policy, not only the TypeSafe judges.** The gateway client, the embedding, reranker and model-tier clients, plur and the Obsidian bridge accepted any `http://` `baseUrl`, so a typo or a crafted config could send the bearer key and vault text in clear to an arbitrary host, or hand them to an `HTTP_PROXY` in the environment. They now share one transport: `https://` is unchanged; every `http://` request, loopback included, is sent directly (no proxy) to the address that was checked, with redirects refused; a host that resolves to any public, link-local or cloud-metadata address is refused at once, whether or not it is listed. The new root `network.plainHttpHosts` lists the exact hostnames a plain `http://` provider URL may name. Compatibility for one release: an unlisted non-loopback host that resolves only to private addresses (loopback, RFC 1918, `fc00::/7`) still works, with a warning that names the host and the config to add; it is refused from the next major release. `obsidian-tc doctor` now lists every plaintext provider host with its resolved address and a status (`allowed`, `deprecated-unlisted`, `refused`), and `server_health` `deprecations` names each unlisted host. On Cave, where the gateway and embeddings URLs are `http://litellm:4000` on a Docker bridge, they keep working; add `network: { plainHttpHosts: ["litellm"] }` to silence the warning. A host that resolves into the Tailscale/CGNAT range `100.64.0.0/10` is allowed only when it is listed (in `network.plainHttpHosts` or a judge block's own `plainHttpHosts`; list only a real tailnet peer, since ISP CGNAT space is not encrypted), shown by `doctor` as `allowed (listed tailnet/CGNAT)`; unlisted, it is refused with no deprecation path.

- **`response_format` on resource reads, links, frontmatter and listings.** `read_resources`, `read_frontmatter`, `list_notes`, `get_outgoing_links`, `get_backlinks`, `get_active_file` and `patch_active_file` accept `response_format: concise|detailed` through the same shared resolver (explicit, then the legacy `verbosity` alias, then `tools.defaults.responseFormat`, then `detailed`). `resources/read` takes no parameters, so only the config default applies to it: `concise` returns the note body without its frontmatter block, and the scope check, vault binding, folder ACL, size ceiling and cache hints are unchanged. `list_notes` concise is `{ vault, notes: [{ path }], next_cursor }`, `get_backlinks` keeps `{ source_path, line }`, `get_outgoing_links` keeps `{ target, line, resolved }` plus the set `heading`, `target_path` and `candidates`, and `read_frontmatter` drops the derivable `has_frontmatter`. Unset and `detailed` output is unchanged; the advertised output schemas mark the concise-dropped fields optional. Part of #1027.

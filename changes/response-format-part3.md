- **`response_format` on listings, search-and-read, graph search, memory and episode reads.** `list_attachments`, `list_periodic_notes`, `list_snapshots`, `list_capture_queue`, `list_goals`, `search_and_read`, `vault_graph_search`, `knowledge_search`, `get_entity`, `query_entity_graph`, `get_session_traces`, `session_bootstrap`, `work_episodes`, `work_episode_chain`, `work_search`, `gap_report`, `rewrite_link` and `prune_hub_links` accept `response_format: concise|detailed` through the shared resolver, and `tools.defaults.responseFormat` now reaches the attachments, periodic-notes, memory, knowledge-search and experiential tools too. Concise keeps what a caller acts on and every safety signal (`poison_assessment` on capture-queue items, a redacted `to_target`, the trust and eligibility of an episode, `valid_to` and `superseded_by` on a retired observation, `size_bytes` on a truncated note) and drops echoes, derivable fields and retrieval provenance; `rewrite_link` and `prune_hub_links` trim only a real run, so a dry run keeps its preview. The user docs list the tools reviewed and left without the parameter (`list_tags`, `list_properties`, `list_vaults`, `list_bookmarks`, `list_workspaces`, `list_kanban_boards`, `list_commands`, `list_quickadd_actions`, `list_templates`, `list_tasks`, `list_contradictions`, `episode_stats`, `find_orphans`, the `plur_*` proxies), and a test fails for any newly registered tool that is neither covered, exempt nor on the not-yet-covered list. Unset and `detailed` output is unchanged; the advertised output schemas mark the concise-dropped fields optional. Part of #1027 (#1075).

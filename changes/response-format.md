- **Shared `response_format: concise|detailed`.** `read_note`, `read_notes`, `write_note`, `append_note`, `patch_note`, `update_frontmatter`, `find_notes_by_property`, `find_unresolved_links`, the search tools and `note_quality_report` accept `response_format`; `concise` returns only the high-signal fields (a write acknowledgement is `{ vault, path, content_hash }`, a `read_note` is the body without frontmatter), cutting the characters an agent pays per call. A new `tools.defaults.responseFormat` config key sets the format for calls that name none; it ships as `detailed`, so output is unchanged until a call or the config opts in. Precedence is explicit `response_format`, then the legacy `verbosity` alias, then the config default, then `detailed`. Safety signals (`quality_warning`, non-`none` `poison_assessment`, `redactions`, `patch_note` removal counts) and errors are never trimmed. The advertised output schemas mark the concise-dropped fields optional. Part of #1027.

- **List and search tools now return smaller default pages, and the whole-note readers tell Claude Code how large their results may be.** Clients cap what they show the model (Grok Build inlines about 20 KB and drops `resource_link`; claude.ai about 150,000 characters; Claude Code saves a text result over 50,000 characters to a file), so every list or search tool's default page now stays under 20 KB on a large vault, by lowering the default item count rather than cutting a result mid-item. `list_notes`, `list_attachments`, `find_notes_by_tag`, `find_notes_by_property`, `get_backlinks`, `find_orphans` and `find_unresolved_links` default to 100 items (were 200 or 500); the last five gain a `cursor` input and a `next_cursor` output to reach the rest. `search_text`, `search_regex`, `search_jsonlogic`, `search_vault` and `list_tasks` default to 25 (were 50). `find_link_cycles` defaults to 10 cycles (was 50) and reports only cycles of at most `max_length` links (default 10), counting the others in `skipped_longer`. `vault_graph_search`, `knowledge_search` and `diagnose_retrieval` default `final_top_k` to 10 (were 20 to 30), and the plugin-backed `list_commands`, `makemd_query`, `query_datacore`, `search_omnisearch` and the capture, trace and docs listings default to 50 to 100 (were up to 1000). Pass `limit` for a larger page. `governor.maxResponseBytes` is unchanged. The whole-note readers (`read_note`, `read_notes`, `read_resources`, `read_snapshot`, `fetch`, `search_and_read`, `bundle_files`, `bundle_folder`, `get_active_file`, `session_bootstrap`) now advertise `_meta["anthropic/maxResultSizeChars"]` in `tools/list` (the governor ceiling, capped at Claude Code's 500,000), and no other tool does. `get_attachment` gains a text `description` (type, pixel size, file size) and `include_content: false` for a client that cannot use the base64 bytes. No tool returns a `resource_link` or an embedded resource. See Tools, "Result size and paging".

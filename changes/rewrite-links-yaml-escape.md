- **Renaming or repointing a link no longer corrupts the frontmatter of notes that link through a property.** `rewrite_link`, `move_note` (backlink maintenance), bulk moves and attachment moves repoint links in properties such as `up: "[[Old]]"`, but pasted the new target into the YAML as raw text. A target with a `"`, a backslash, a `'` in a single-quoted value, `: ` or ` #` in a plain value produced a broken block (`up: "[[a"b]]"`) that no tool could read back. The new target is now written as a YAML value in the scalar's own quoting style (double-quoted: JSON escapes; single-quoted: doubled quote; plain: unchanged unless that would change the meaning, then double-quoted; block scalars: literal text), and the block is re-parsed to prove the property holds the intended link text. A property that cannot be proven is left byte-identical while the note's body links are still rewritten; `rewrite_link` and `move_note` name it in `warnings`. Other keys, comments and spacing are untouched. Unquoted `[[X]]` in frontmatter (a YAML nested list, not a link) and links in frontmatter comments are no longer rewritten.

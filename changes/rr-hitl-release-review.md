- **Human confirmations fail closed and bind the right state (release-review fixes).** A confirmation can no longer be rebound to newer target state: the rendered `obsidian-tc elicit` command now carries `--state-fp` (the fingerprint of the request it was shown for), so repeating a blocked call after its target changed makes an earlier command fail with `replay_drift` instead of approving the newer state; recorded requests also expire after 24 hours on lookup, not only on write. If the target's state cannot be read (a hard-linked file, an unreadable repository state for `git_commit`) the call now fails with that refusal (`acl_denied`, or a refusal naming no cause) instead of raising an unbound request that approved whatever the file held at redemption. A call cancelled while dispatch awaits (throttle backend, provenance hashing) is now stopped before the confirmation token is spent and before its handler runs. `update_active_file` completes in-band confirmation: the form is sealed for the tool that actually raised the gate (`write_note`), where it used to loop to "approval not obtained" and leave the note unchanged. The confirmation form and error for every active-file tool now name the resolved note (`delete_active_file` named none), a throttled active-file call no longer reaches the companion plugin first, and the folder ACL answers before the markdown-type check so a denied non-markdown note reads like a denied markdown one. Completion, cache-reset and confirmation-consumed telemetry is filed under the vault a call acted on rather than the stdio placeholder it started from, and a denied `read_resources` item no longer emits a second `tc.tool.call.completed`. An elicitation `decline` is unchanged: a hard stop with no mint route. The 1.31.4 release notes no longer state a tool count that has since moved.

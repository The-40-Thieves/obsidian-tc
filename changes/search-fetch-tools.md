- **Standard `search` and `fetch` tools for ChatGPT deep research and company knowledge.** `search(query)` returns `{results: [{id, title, url, text}]}` over the existing hybrid search (`search_vault` mode `auto`), one result per note; `fetch(id)` takes a result's id and returns `{id, title, text, url, metadata}`, the full note text with an absolute citation `url`. Both return that object as `structuredContent` and as JSON in the text block, declare object-rooted output schemas, and apply the same read-ACL checks as `read_note` (a denied note is absent from `search` and `fetch` refuses it with `read_note`'s error). The citation url is `obsidian://open?vault=…&file=…` by default, or `<publicUrl>/<note path>` when the new opt-in `vaults[].publicUrl` (an https base, for example an Obsidian Publish or Quartz site) is set. Both tools are in the `core` profile, and the default `triad` surface now advertises them beside `find_capability`, `describe_capability` and `call_capability` (five tools instead of three; hide them with `toolVisibility.hidden: [search, fetch]`).

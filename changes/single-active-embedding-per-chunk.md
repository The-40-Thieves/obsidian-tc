- **A chunk can no longer carry two active embeddings, and when the state is wrong it now says so instead of silently emptying the dense index.** Nothing enforced one `is_active = 1` row per chunk in `chunk_embeddings`; a writer outside the two ingest paths that left a stale model active beside the current one made the active-model lookup arbitrary, so `vec_chunks` rebuilt to 0 rows with every embedding present and every unchanged note was reported as a "concurrent write" skip on every pass (GH #1160). Migration `20261008_001` deactivates the older generation of any chunk already in that state (newest `generated_at` wins, the lower model string breaks a tie; rows are kept, never deleted) and makes `idx_chunk_embeddings_active` UNIQUE, so a second active row is refused at the offending write. Both ingest writers (and the embedder-arms eval loader) now retire the other models' rows before activating the new one. A `vec_chunks` rebuild that lands under half of the active embeddings, or finds a double-active chunk, logs a `[vec] WARNING` naming the counts and where the active rows are, and carries `shortfall` on its rebuild event. The stale-plan skip message now states what differed (for example the planned versus found `active_model`), names a chunk with several active embeddings, and says when the same skip repeats across passes. `doctor --probe` gains `index.embeddings`: it fails on a double-active chunk and warns when `vec_chunks` disagrees with the active embeddings at the configured width.

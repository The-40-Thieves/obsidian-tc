- **A task-backed tool call keeps every policy it would have met synchronously, and a superseded or cancelled one can no longer misreport.** The background task for `index_vault` was built from a hand-copied subset of the caller's context, which dropped a persona's `toolVisibility`: a persona that disabled `external-network` was refused `index_vault` when called directly, and served it as a task, sending vault content to the embedding provider. The context that crosses into a task is now one typed table (every context key is carried, rebuilt by the worker, or dropped with a reason, and a test fails when dispatch reads a key the table does not list), and a call that dispatch would refuse is refused up front instead of being queued. Registering a tool that is both `taskAugmentable` and confirmation-gated now fails at startup, because its confirmation round runs after the task is created. Each attempt of a task now holds its own lease token and every write about the job (outcome, completion) is refused for a superseded attempt, so a lapsed lease no longer lets two runs of one `index_vault` overwrite each other; `index_vault` stops when its call is cancelled (it ignored the signal before); a task that finished before a late cancel arrived is reported `completed` with its result, not `cancelled`; and a shutdown now aborts and waits for the task runs the server started itself, leaving them to be recovered by lease expiry.

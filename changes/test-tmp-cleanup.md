- **The test suites no longer leak temp directories.** A full server run left thousands of `obtc-*`, `tc-*`, `check-*` and `where-*` directories (plus 400-600 MB `obtc-reranker-auto-select-*` stage copies and vitest's own `<nanoid>/ssr` module cache) in the system temp dir, enough to fill a 45 GB root disk. Fixtures now create directories through one helper, `makeTempDir()` in `packages/server/test/tmp.ts`, which removes them when the test file ends even if an assertion threw, and the helpers that returned a second cache directory remove it too. A vitest `globalSetup` (`test/tmp-guard-global-setup.ts`) points `TMPDIR` at a private per-run root, one subdirectory per test file, and fails the run naming every file that leaves an entry behind, then deletes the root; vitest's own leaked cache directory is removed there as well. `bun run test:scripts` runs under the same check through `scripts/with-tmp-guard.mjs`. The private root is derived from `os.tmpdir()`, so it behaves the same on Linux, macOS and Windows runners and cannot blame this run for another process's entries.

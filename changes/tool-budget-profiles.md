- **Tool-budget profiles, selectable per URL.** A client that caps the tools it accepts can now connect to `/mcp/essentials` (about 35 curated tools, advertised flat, no meta-tools), `/mcp/core` (the existing `core` curation, flat), `/mcp/full` (every tool, flat), or `/mcp/triad` / `/mcp/domain`; `/mcp` is unchanged. The new `toolFacade.advertise` (`all`, `core`, `essentials`; default `all`) picks one for the whole server, and stdio uses it as its only selector. Profiles only change what `tools/list` advertises: every tool stays callable by name under the same authorization. The server `instructions` now open with a routing sentence for the surface the client was given, complete within the first 512 characters, and the triad tools, with the `search` and `fetch` advertised beside them, carry `_meta` `"anthropic/alwaysLoad": true` so Claude Code loads them upfront.
- **OAuth works on every profile URL.** With `auth.resource` set to the `/mcp` URL, a client given `/mcp/essentials` (or `core`, `full`, `triad`, `domain`) is challenged with a Protected Resource Metadata URL that is served, and the document names the URL it was given, so clients that compare the two sign in. The bundled authorization server accepts a `resource` indicator equal to `auth.resource` or to `auth.resource` plus one of those names (exact match, never a prefix; unknown names stay refused), issues `aud` for the one requested and keeps it across refresh; a token for any of them is accepted on every surface, since profiles never change what is authorized. With an external authorization server and no explicit `auth.audience`, the same set is the bound audience, and an explicit `auth.audience` is unchanged. `GET`/`DELETE` on an unknown `/mcp/<name>` now answers 404 instead of 405.

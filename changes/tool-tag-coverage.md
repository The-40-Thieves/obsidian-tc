- **Every tool now carries tags, so `toolVisibility.hiddenTags` / `disabledTags` act on the whole surface.** Tags come from one fixed vocabulary (`read-only`, `writes`, `destructive`, `hitl`, `bulk`, `admin`, `plugin-bridge`, `external-network`, `domain:<name>` and the existing topic labels). Most are derived at registration from a tool's scopes, destructive flags, HITL gating and facade domain, so they cannot drift; only `external-network`, a few bridge tools and the topic labels are declared by hand. For example `hiddenTags: ["destructive"]` removes every tool that can destroy data from discovery in every facade mode, and `disabledTags: ["external-network"]` refuses the tools that may call a hosted embedding provider. Registration now throws on a tag outside the vocabulary. `describe_capability` returns `tags`, each tool page lists them, and a new `check:tool-tags` gate audits the live registry (see the Tool tags section of the tool reference).

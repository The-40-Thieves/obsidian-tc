- **A note with unparseable frontmatter YAML is now readable, repairable, and no longer breaks whole-vault tools.** Three gaps shared one error kind (`frontmatter_yaml`). (1) A write that failed to index because of bad YAML was counted as an index write failure (`write_failures`, `last_write_error`), which trips the index-stalled alert on a typo; it now increments `obsidian_tc_index_frontmatter_failures_total` and shows up as `index.frontmatter_failures` (count and last path, cleared when the note is repaired) in `server_health`, with the same stderr hint the reconcile gives, while a real I/O failure still counts as a write failure. `doctor --probe` `index.coverage` also reports notes already indexed whose file on disk is newer than their index row. (2) `read_note` and `read_notes` no longer refuse such a note: they return the content, the body, `frontmatter: null`, `raw_frontmatter`, the parse error with its file line and column, and a repair warning. `update_frontmatter` with `operation: "replace"` repairs it with no approval prompt (there is no parsed metadata to discard) and takes a new `frontmatter_yaml` argument, raw YAML for the whole block that is validated before anything is written and refused with the parse error if still invalid; `prev_hash` and the write ACL apply as before, and every other refusal on such a note now names `update_frontmatter` in its text. (3) `get_backlinks`, `find_orphans`, `find_unresolved_links`, `get_outgoing_links`, `vault_health_score`, `find_link_cycles`, `get_link_strength`, `suggest_links`, `audit_provenance`, `list_properties`, `find_notes_by_property`, `list_tags`, `find_notes_by_tag`, `search_jsonlogic`, `search_vault`, `query_base` and `list_kanban_boards` failed for the whole vault with `invalid_input` when any one note had bad frontmatter; they now return their results for the readable notes plus `warnings` naming the broken notes (readable paths only, capped at 50 with `warnings_omitted`), and the broken note's body links still count. Attachment reference scans and `bundle_notes` read only note bodies and no longer throw on such a note either.

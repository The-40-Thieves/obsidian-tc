- **Every read of a vault file now refuses a hard link, and the search tools share one stored-row identity rule.** `vault_context` in bootstrap mode (no `query`) read `memory/_next-session.md` with a bare `readFileSync`, so a note the caller could read that was a hard link to an ACL-denied private note fed up to 600 characters of the private note into retrieval; it now reads through the same opened-descriptor guard `read_note` uses and fails with `acl_denied`. The same class is closed at the other places that read a vault file without that guard: the `.obsidian` config readers (bookmarks, workspaces, periodic-note settings, the attachment folder, plugin manifests and the enabled-plugin list), session trace replay, the reflections scan of `forget`, and the write-provenance digest. `search_semantic`, `search_text` and the other search tools that judge a stored row now hide a note whose `chunks` and `notes` rows name different ACL identities even when one of them names the note itself, exactly as `vault_context` and the quality and gap readers already did.
- **The same refusal now covers the sandbox copy, the Excluded-files list and the git state; legitimately linked `.obsidian` files fail closed.** `session_rerun` (and `rerun --sandbox`) staged its copy of the vault and the session traces with a dereferencing `cpSync`, which followed symlinks (out-of-vault targets too) and turned a hard link into a fresh single-link file, so a call the live vault refused (a `memory/_next-session.md` linked to a denied note) was accepted from the copy and up to 600 characters of it reached the embedding provider; the copy now never follows a symlink and leaves out a file with more than one link. `.obsidian/app.json` (the Excluded-files list) was read by path after an `lstat` with no link check, and its value was persisted and printed by the index-coverage doctor; it now reads through the opened-descriptor guard and a linked file keeps the last good list. `git_commit`'s `state_fp` was derived from `.git/HEAD`, the refs, `packed-refs` and the index read with no link check; a hard-linked or symlinked git metadata file now makes the call refuse instead of fingerprinting it. **Compatibility:** a hard-linked or symlinked file under `.obsidian` is no longer read: `bookmarks.json` and `workspaces.json` fail with a typed `acl_denied` naming the file, periodic-note and attachment settings fall back to their defaults, and a linked plugin `manifest.json` is not listed. Replace the link with an ordinary file (see the folder ACL page).

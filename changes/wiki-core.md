- **`draft_wiki_page` and `commit_wiki_page` (full profile).** A wiki page workflow where the server does the bookkeeping and the LLM writes the prose. `draft_wiki_page` (read-only) runs the `find_existing_page` duplicate check and returns the existing page if there is one, a link map (notes to link to, notes that should link back, notes already linking), the page type's requirements from the wiki folder's `SCHEMA.md` and a changeset skeleton; it writes nothing. `commit_wiki_page` applies the changeset atomically: one new page plus additive `link` / `append` patches on existing notes. Every path is checked (write ACL, `prev_hash`, poison and memory-defense scans) before the first write, a failing write rolls the earlier ones back, and the commit is one provenance record listing every touched path. Creating a page and patching need no confirmation (snapshots and `restore_note` are the undo); overwriting an existing page asks like `write_note`. A page that duplicates an existing one is refused unless `allow_duplicate` is set; schema, link and coverage findings come back as `problems` instead of blocking. New config `vaults[].wiki.folder` names the wiki folder; its `SCHEMA.md` declares page types, required frontmatter and the property vocabulary. See "Wiki workflow" in the tools docs. Generated `index.md` / `log.md` pages are not part of this change.

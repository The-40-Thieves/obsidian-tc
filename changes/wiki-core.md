- **`draft_wiki_page` and `commit_wiki_page` (full profile).** A wiki page workflow where the server does the bookkeeping and the LLM writes the prose. `draft_wiki_page` (read-only) runs the `find_existing_page` duplicate check and returns the existing page if there is one, a link map (notes to link to, notes that should link back, notes already linking), the page type's requirements from the wiki folder's `SCHEMA.md` and a changeset skeleton; it writes nothing. `commit_wiki_page` applies the changeset as one all-or-nothing unit on errors: one new page plus additive `link` / `append` patches on existing notes. The page must be inside the configured wiki folder, judged as the same directory on the filesystem rather than by comparing spellings (a vault without one refuses); the tool needs `read:notes` as well as `write:notes`. Every path is checked (write and read ACL, `prev_hash`, poison and memory-defense scans) before the first write; the temp files are staged, a `pending` provenance record is written, and each existing note is re-hashed right before it is replaced, so an edit made meanwhile aborts the batch and is kept; a failing write rolls the earlier ones back without overwriting or deleting anything written since (an incomplete rollback keeps the snapshots for `restore_note`). It is not crash-atomic: a process crash mid-rename can leave a partial batch, which the `pending` provenance record and the per-note snapshots make recoverable. Creating a page in the wiki folder and patching need no confirmation (snapshots and `restore_note` are the undo); overwriting an existing page asks like `write_note`. A page that duplicates an existing one is refused unless `allow_duplicate` is set; schema, link and coverage findings come back as `problems` instead of blocking. New config `vaults[].wiki.folder` names the wiki folder (a plain relative folder; `.`, `/`, `""`, absolute paths and `..` are rejected); its `SCHEMA.md` declares page types, required frontmatter and the property vocabulary. See "Wiki workflow" in the tools docs. Generated `index.md` / `log.md` pages are not part of this change.

- **Generated `index.md` and `log.md` in the wiki folder.** In a vault with `vaults[].wiki.folder` the server now writes two pages itself, marked `generated_by: obsidian-tc`: `index.md` lists the folder's pages grouped by their `SCHEMA.md` type with links (built from the vault, never maintained by an LLM), and `log.md` is an append-only projection of the write provenance chain for the folder, one greppable line per change (`time | op | path | principal | model | tool#seq`), with the last projected provenance sequence kept in its frontmatter so a re-run never repeats a line. `commit_wiki_page` regenerates both after each write, and the new opt-in `maintenance.wikiPages` (`enabled`, `intervalHours`, default 6) does it on a schedule. Both list only paths a reader holding no rule-scope may read under the vault's ACL, never an Excluded note, so a page in a read-denied folder is never named; they are written inside the wiki folder only, with a snapshot of what they replace and no confirmation; a generation failure is a `generated_page` problem on the commit response, never an error. A hand-edited page (a hash in its frontmatter seals it), or a person's own `index.md` with no marker, is never overwritten: it is reported as a `generated_page` problem and by the new `generated_pages` check of `lint_wiki`, and deleting it lets the next pass rebuild it. Duplicate-topic detection, `lint_wiki`, `find_orphans`, `find_unresolved_links` and `audit_provenance` skip both files, and their links no longer count as inbound links. The log lags one write (a commit's own change shows up at the next regeneration). See "Generated index and log pages" in the tools docs and "Server-generated wiki pages" in SECURITY.md.

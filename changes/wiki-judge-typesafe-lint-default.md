config-schema-change: wikiJudge, maintenance.wikiLint.judge
---
- **The wiki lint judge is on by default once a judge is configured, and can run on TypeSafe Jev.** `lint_wiki` now judges near-duplicate pairs unless the call passes `judge: false` or `wikiJudge.lintEnabled` is `false` (new, default `true`), and `maintenance.wikiLint.judge` defaults to `true`; both still need a configured judge and `wikiJudge.maxCallsPerDay` above 0, the scheduled pass still needs `maintenance.wikiLint.enabled`, and the judge only adds a verdict to a proposal. `find_existing_page` stays off by default (`wikiJudge.enabled: false`). The new experimental `wikiJudge.provider: typesafe` asks TypeSafe Jev a Choice question over `same_topic`, `overlapping` and `different` instead of the gateway `judge` role, with `model` (a pinned, dotted version), `threshold` (no default; a ranking score, not a security control), `apiKeyEnv`, `baseUrl` and `allowPlainHttp`, built through the same client and egress checks as `experiential.citationInfer.judge`. `lint_wiki` now carries the `external-network` tag because the judge can send note text out: `toolVisibility.disabledTags: ["external-network"]` removes it, and the scheduled sweep skips its judge under that tag. `obsidian-tc doctor` reports the judge provider and the lint default. A pre-registered comparison on the public corpus found Jev non-inferior to the gateway judge on held-out note pairs at the registered margin (method and decision in the Wiki checks docs; TypeSafe's agreement bars publishing the figures, so none are given), so Jev is the recommended lint-judge provider on Cave; the gateway judge stays the default provider.

- **Raw-source ingest for the wiki: an immutable raw folder and `draft_wiki_page` `source`.** Each vault with a wiki now has a raw-sources folder, the new `vaults[].wiki.rawFolder` (validated like `wiki.folder`; default `raw` BESIDE the wiki folder, so `wiki` gives `raw` and `notes/wiki` gives `notes/raw`, and none when that would be the wiki folder itself; it must not be, contain or sit inside the wiki folder). Its files are immutable: the folder ACL gains a derived per-vault rule, not a config key, so no tool can write, create, rename or delete anything in it whatever `writePaths` or `deletePaths` say, judged on the path as written and on the real path it leads to (a symlink in or out does not make a source writable), and `commit_wiki_page` refuses any page or patch that targets it. Add sources outside the server. **A vault that already has a `raw/` folder next to its wiki folder now has it locked: set `wiki.rawFolder` to another name to keep it writable.** `draft_wiki_page` takes `source`, one markdown note in the raw folder: it is cited in the skeleton's `sources`, reported in a new `ingest` section (size, title, content hash, the wiki pages that already cite it), and a source under 1500 characters is refused a page of its own (no changeset, `ingest.refused`) when no page in the wiki covers, relates to or cites it, because a page for it would only restate it. Raw notes are inputs, never dedupe candidates or patch targets, so a raw clipping that shares a topic's name no longer reads as an existing page. A source the caller may not read answers like a missing one, and one outside the raw folder, or reached through a symlink that leaves it, is refused like a page outside the wiki folder. The server writes no prose and calls no model here beyond the existing optional dedupe judge, which never sees a raw note. See "Ingesting a raw source" in the tools docs. **Link maintenance never rewrites a raw note.** `move_note`, `bulk_move_notes` and `move_attachment` keep their deliberate carve-out (they repoint links in notes outside the write whitelist), but one shared guard now keeps it off immutable paths: the move proceeds, raw notes that link the moved target are left alone, and the result lists them (`immutable_not_updated` for notes the caller may read, `immutable_not_updated_hidden` as a count for the rest, `immutable_warning` that those links still point at the old name). **A raw folder that is a symlink is locked under its target too** (resolved when the server starts, so a symlink made later takes effect at the next restart), the wiki and raw folders are compared by filesystem identity (a vault where they are one directory is refused at startup), and a raw folder that leaves the vault or whose identity cannot be established locks nothing extra and is refused for ingest (`raw_folder_unsafe`). A read-denied symlink in `raw/` now answers `note_not_found` like a missing file, and a folder name containing `*`, `?` or `[` is matched literally.

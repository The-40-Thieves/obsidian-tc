- **Raw-source ingest for the wiki: an immutable raw folder and `draft_wiki_page` `source`.** Each vault with a wiki now has a raw-sources folder, the new `vaults[].wiki.rawFolder` (validated like `wiki.folder`; default `raw` BESIDE the wiki folder, so `wiki` gives `raw` and `notes/wiki` gives `notes/raw`, and none when that would be the wiki folder itself; it must not be, contain or sit inside the wiki folder). Its files are immutable: the folder ACL gains a derived per-vault rule, not a config key, so no tool can write, create, rename or delete anything in it whatever `writePaths` or `deletePaths` say, judged on the path as written and on the real path it leads to (a symlink in or out does not make a source writable), and `commit_wiki_page` refuses any page or patch that targets it. Add sources outside the server. **A vault that already has a `raw/` folder next to its wiki folder now has it locked: set `wiki.rawFolder` to another name to keep it writable.** `draft_wiki_page` takes `source`, one markdown note in the raw folder: it is cited in the skeleton's `sources`, reported in a new `ingest` section (size, title, content hash, the wiki pages that already cite it), and a source under 1500 characters is refused a page of its own (no changeset, `ingest.refused`) when no page in the wiki covers, relates to or cites it, because a page for it would only restate it. Raw notes are inputs, never dedupe candidates or patch targets, so a raw clipping that shares a topic's name no longer reads as an existing page. A source the caller may not read answers like a missing one, and one outside the raw folder, or reached through a symlink that leaves it, is refused like a page outside the wiki folder. The server writes no prose and calls no model here beyond the existing optional dedupe judge, which never sees a raw note. See "Ingesting a raw source" in the tools docs.

type: Security

- **A rename can no longer inject text into the notes that link the old name.** `move_note`, `bulk_move_notes`, `move_attachment` and `rewrite_link` write the new target into the `[[...]]`, `![[...]]` and `[text](...)` of every note that linked the old one, including notes the caller cannot read, and `update_backlinks` is on by default with no confirmation for a same-folder rename. A destination such as `foo]]`, a newline, then text closed the wikilink early and wrote that text into every linking note. A NEW note or attachment name (create, move, rename or copy) containing `[`, `]`, `#`, `^`, `|`, `%%`, a newline or any other control character is now refused with `invalid_input` naming those characters; a file that already has such a name stays readable and updatable. Independently, every link the rewrite changes is parsed again and must be exactly one link to the intended target (heading and alias unchanged, nothing around it), or the call is refused and no note is changed; this also covers `rewrite_link`'s free-text `to_target`. Behaviour change: a `to_target` containing a line break, `|` or `]]` is refused, and so are `#`, `^`, `[` and `]` in a new note name. The frontmatter (YAML) half of this class was fixed earlier; a property link's new target must additionally not contain `[[`, `]]`, `|`, `%%` or a line break.

- **Write provenance no longer re-signs a head it has not checked.** Appending a record or pruning for retention now validates the committed chain head first (it exists, pins the real last record, its prune anchor matches the first surviving record, and its signature still verifies). A writer of `cache.db` who cannot read the signing key could previously plant a prune anchor or rewind the tail and have the next write sign the forgery, so `provenance verify` passed. Now the forged head is left as found, the write is still recorded with a `head_untrusted` marker that verify reports (and `--allow-unsigned` does not hide), and a signer outage no longer writes an unsigned head over a signed one. The `after` digest of a note write is the content hash the handler returned instead of a later disk read, and for other tools the opened file must be the file the vault-containment check vetted, so a directory swapped for an outside symlink records `unhashable`. Recording stays fail-open, but a missing record is now visible: `obsidian_tc_provenance_faults_total`, a `provenance_fault` event, and a doctor warning.

- **Signed write provenance.** Every committed mutating tool call now appends one hash-chained record to `cache.db`: the tool, the vault, the paths the call named with sha256 digests before and after (never content), the time, and attribution split into `verified` (host, server version, transport, and the principal and persona only when a bearer token was cryptographically verified), `unauthenticated` and `self_reported` (client name and version, and the `_meta` `io.obsidian-tc/provenance` model, project, agent and machine, which a client can lie about). Records are signed with the auth registry's active EdDSA key (`obsidian-tc auth rotate-key --alg EdDSA`) and a signed head row catches a removed last record; a stdio-only deployment has no registry key and is chain-only. New `obsidian-tc provenance verify [--vault <id>] [--json] [--allow-unsigned]` (exit 1 on failure; unsigned records fail unless `--allow-unsigned`), a `provenance.chain` doctor check, and a new `provenance` config block (`enabled`, `host.mode` of `hashed` or `label`, and `retentionDays`, unset by default, which prunes the oldest records through the maintenance sweep while keeping the chain verifiable). See the security docs, "Write provenance".

# Observability Model (G2.4)

**Status (THE-598, 2026-07-27):** this is a point-in-time G2 design document (same "design-era" convention used in [`G2.1-tools.md`](G2.1-tools.md) and [`G2.3-storage.md`](G2.3-storage.md)), not a living reference. Two things it proposed never shipped and are **not** in the current schema: the verbose child-span hierarchy (marked below) and any sampling/detail-level knob — `packages/server/src/otel/tracing.ts` records both as deliberately deferred to a later release. Config-key spellings below have been corrected to the shipped camelCase JSON shape (`packages/shared/src/config.schema.ts`); the Prometheus catalog is docgen-generated and stays current. For the always-current, generated field reference use `docs/wiki/Configuration.md` (`BEGIN GENERATED: config`); for the living operator-facing page use [`docs/wiki/Observability.md`](wiki/Observability.md) and [`docs/src/content/docs/observability/otel.md`](src/content/docs/observability/otel.md).

obsidian-tc emits three observability streams: OTEL traces, Prometheus metrics, and MORGIANA CloudEvents. Each is opt-in beyond a sensible local default, and none of them block tool execution if the export path fails.

## Pillars

| Stream            | Purpose                                                       | Default                            |
| ----------------- | ------------------------------------------------------------- | ---------------------------------- |
| OTEL traces       | Per-call structured spans for debugging and latency analysis. | stdout in dev; off in production.  |
| Prometheus metrics | Aggregate counters, histograms, gauges for SLOs and alerting. | Endpoint disabled (`:0`).          |
| MORGIANA events   | Structured CloudEvents for security and ops audit.            | Local JSONL spool, on by default.  |
| JSONL traces      | Full per-call replay corpus (specified in G2.3 D8).           | On by default per vault.           |
| `event_log` table | Local SQLite audit table (specified in G2.3 D9).              | On by default per vault.           |

## OTEL traces

### Span model

One root span per tool call. Span name: `obsidian_tc.<tool_name>`. Span kind: `SERVER`.

**Proposed, never shipped:** a verbose detail mode adding child spans per dispatch phase:

| Child span                     | Would have captured                               |
| ------------------------------ | ------------------------------------------------- |
| `obsidian_tc.auth_check`       | JWT validation                                    |
| `obsidian_tc.acl_eval`         | Scope check, folder ACL evaluation                |
| `obsidian_tc.policy_eval`      | HITL, idempotency, rate limit                     |
| `obsidian_tc.tool_impl`        | Actual tool execution                             |
| `obsidian_tc.output_serialize` | Response serialization, governor truncation       |

`src/otel/tracing.ts` records the reconciliation explicitly: instrumenting this means fracturing dispatch's tightly-coupled inline stages for marginal value at laptop scale, so it is deferred to v1.x. **The shipped behavior emits the root span only, unconditionally — there is no config key that changes this.**

### Attributes

```
service.name                  = "obsidian-tc"                       # resource attribute
service.version               = <semver>                            # resource attribute
service.instance.id           = <pid + start_ts>                    # resource attribute
obsidian_tc.vault_id          = <vault>
obsidian_tc.tool              = <tool_name>
obsidian_tc.caller_hash       = <sha256(caller_id)[:8]>
obsidian_tc.scopes_required   = <comma-list of scope strings>
obsidian_tc.status            = "ok" | "denied" | "error"
obsidian_tc.error_code        = <code | absent>
obsidian_tc.elicit_used       = bool
obsidian_tc.overflow_b        = <number, 0 if no truncation>
obsidian_tc.duration_ms       = <number>
rate_limit.hit                = bool
```

13 attributes as shipped (3 resource + 10 span, `packages/server/src/otel/attrs.ts`'s `SPAN_ATTR`) — an `obsidian_tc.idem_hit` attribute was proposed here and never implemented; it is not in `attrs.ts` and does not appear on a span.

Caller identity is hashed to 8 hex chars to bound cardinality.

### Sampling — proposed, never shipped

There is no sampling knob and no `traceDetail`/detail-level switch in the shipped schema. Every dispatch is traced, unconditionally, whenever tracing is enabled (`observability.otel.endpoint` set). The subsection below is retained as the original design proposal.

#### Original proposal (not implemented)

`observability.traces_sample_rate: 1.0` was proposed as the V1 default (laptop scale, traces are cheap), with error spans always sampled regardless of rate. None of this was built — see "Sampling" above.

### Export

OTLP HTTP. `observability` is a single **global** block (not per-vault):

```yaml
observability:
  otel:
    endpoint: "http://localhost:4318"   # OTLP HTTP receiver
    headers:
      Authorization: "Bearer ${OTEL_TOKEN}"
```

Default: off (no exporter created) unless `observability.otel.endpoint` is set. MORGIANA can be the configured endpoint.

## Prometheus metrics

### Catalog

<!-- BEGIN GENERATED: metrics-catalog -->
obsidian-tc maintains a Prometheus catalog of **24 counters, 4 histograms, 16 gauges**. The recorder is always live so the `get_metrics` tool and the optional `/metrics` scrape endpoint share the same in-memory state. Every catalog name below is registered so `/metrics` is catalog-complete even before a metric has live traffic to report.

### Counters

| Name | Labels | Help |
|---|---|---|
| `obsidian_tc_acl_denied_total` | `reason`, `scope_class`, `vault` | ACL/scope denials by vault, scope class, and reason. |
| `obsidian_tc_activation_recompute_chunks_total` | `vault` | Chunks whose cached_activation_score was recomputed by the periodic ACT-R activation job, by job name. Cumulative. A flat line while the scheduler reports the job running means chunk_retrievals has stopped growing, not that the job stalled. |
| `obsidian_tc_audit_write_failed_total` | `tool`, `vault` | Security-audit event writes that failed, by vault and tool. Audit is fail-open by design (a failed write must never break dispatch), so this counter is the only signal that the audit trail has gone lossy. |
| `obsidian_tc_auth_rejections_total` | `reason` | Refused tokens at the HTTP edge, by rejection reason. |
| `obsidian_tc_embed_batch_rejections_total` | `vault` | Embed requests the provider rejected for exceeding its context (HTTP 400/413), then bisected + retried, by vault. Each is an extra round-trip; a persistent count means embeddings.maxBatchTokens is too high. |
| `obsidian_tc_governor_truncations_total` | `tool`, `vault` | Response-byte governor truncations/refusals, by vault and tool. |
| `obsidian_tc_hitl_elicited_total` | `tool`, `vault` | HITL elicit confirmations required, by vault and tool. |
| `obsidian_tc_idempotency_cache_skipped_total` | `tool`, `vault` | Idempotency results skipped over the byte cap, by vault and tool. |
| `obsidian_tc_idempotency_hits_total` | `tool`, `vault` | Idempotency cache hits, by vault and tool. |
| `obsidian_tc_index_write_failures_total` | `vault` | Notes skipped in a pass because the embed provider rejected them even at single-text size, by vault. Unlike the batch rejections above these are NOT retried within the pass, so the note is absent from the index until the next reconcile. |
| `obsidian_tc_ingest_dedup_skipped_total` | `vault` | Chunks whose embedding was reused from an identical-body sibling instead of recomputed, by vault. This is work AVOIDED, so a rise is good ONLY for the chunks it actually resolved — see obsidian_tc_ingest_dedup_unresolved_total for the subset that copied nothing; a fall in this counter means the dedup path stopped matching. |
| `obsidian_tc_ingest_dedup_unresolved_total` | `vault` | Chunks skipped for embedding by cross-path dedup whose source had no stored vector to copy, by vault. A rise is BAD — these chunks are FTS-only (no dense/sparse/colbert) until the owner note re-embeds successfully; it is the loss side of obsidian_tc_ingest_dedup_skipped_total, not work avoided. |
| `obsidian_tc_ingest_secrets_skipped_total` | `vault` | Chunks the secret gate refused to index, by vault. Non-zero is expected on a vault containing credentials; a SUDDEN rise means content that used to index no longer does. |
| `obsidian_tc_morgiana_emit_dropped_total` | `reason`, `vault` | MORGIANA events dropped, by vault and reason. |
| `obsidian_tc_output_schema_drift_total` | `tool`, `vault` | Handler payloads that did not match their advertised outputSchema, by vault and tool. In production this is WARN-only — the payload still ships — so a non-zero value is the only signal that a tool's declared contract has drifted from what it returns. In dev/CI the same condition is a hard internal_error. Any non-zero count names a tool whose schema or handler is wrong; there is no benign case. |
| `obsidian_tc_rate_limit_hits_total` | `scope_class`, `vault` | Rate-limit refusals, by vault and scope class. |
| `obsidian_tc_retrieval_content_bytes_in_total` | `stage`, `vault` | Content bytes materialized entering a stage boundary, by vault and stage. Populated only at candidateAssembly (pre-dedup, across streams) and diversity/gatedRerank (pre-top-K-cut). Compare to the _out_ counter for the same stage: the gap is hydrated content that was never used. |
| `obsidian_tc_retrieval_content_bytes_out_total` | `stage`, `vault` | Content bytes surviving a stage boundary, by vault and stage. See the _in_ counter. |
| `obsidian_tc_retrieval_stage_candidates_in_total` | `stage`, `vault` | Candidates entering each graph-search stage, by vault and stage. Divide the _out_ counter by this for the stage's pass-through ratio: a stage sitting at 1.0 is no longer filtering anything while still costing its latency. |
| `obsidian_tc_retrieval_stage_candidates_out_total` | `stage`, `vault` | Candidates leaving each graph-search stage, by vault and stage. See the _in_ counter. |
| `obsidian_tc_sql_busy_total` | `reason`, `txn`, `vault` | Write transactions that failed on a busy database, by vault, transaction, and reason. reason=busy means contention outlived busy_timeout (5s) — the writers genuinely overlap that long. reason=snapshot is a BUG REPORT, not tuning: it can only be produced by a deferred BEGIN that read and then tried to write, a failure busy_timeout cannot retry, so any non-zero count names a write path still using BEGIN where it should use inWriteTransaction. |
| `obsidian_tc_tool_calls_total` | `status`, `tool`, `vault` | Tool calls by vault, tool, and terminal status. |
| `obsidian_tc_vec_fallback_total` | `reason`, `vault` | Searches that abandoned the vec0 KNN index for the exhaustive brute-force scan, by vault and reason. Results stay correct; the cost profile does not. reason=error is usually a dimension mismatch after an embedding-model change (the index no longer matches the query) and a persistent count means a real misconfiguration; reason=underfill means ACL-invisible chunks may be crowding out visible ones, so the over-fetch could not fill k visible hits. |
| `obsidian_tc_vec_rebuild_total` | `reason` | vec_chunks DROP+rebuild events, by reason. legacy_shape is a one-time pre-partition upgrade; fingerprint_changed means the embedding provider/model/dimensions, distance metric, or chunk/enrichment representation changed since the index was built. Either way every vault's dense index is cold until it re-embeds — any non-zero count outside a deliberate model migration is worth investigating. |

### Endpoint

Server process exposes `/metrics` on `observability.prometheus.port` (default `9464`, only when `observability.prometheus.enabled` is true — the endpoint is off by default, not merely bound to port 0). Bind localhost only by default; non-localhost bind triggers the same hardcoded JWT requirement as MCP transport (G2.2 commitment 8).

```yaml
observability:
  prometheus:
    enabled: true
    port: 9464
    bind: "127.0.0.1"
```

### Cardinality notes

Caller hash is deliberately omitted from Prometheus labels. Prometheus' cardinality budget is tighter than OTEL's, and caller-dimension breakdowns belong in traces and MORGIANA events. Use scope class instead of full scope strings for the same reason.

## MORGIANA events

### Envelope

CloudEvents 1.0:

```jsonc
{
  "specversion": "1.0",
  "id": "<uuid>",
  "source": "obsidian-tc/<vault_id>",
  "type": "<event_type>",
  "datacontenttype": "application/json",
  "time": "<rfc3339>",
  "data": { ... }
}
```

### Event types

| Type                          | Emission point                                          |
| ----------------------------- | ------------------------------------------------------- |
| `tc.tool.call.completed`      | Every tool call (success or failure).                   |
| `tc.acl.denied`               | Scope or path denial.                                   |
| `tc.elicit.requested`         | Policy layer issued an elicit token.                    |
| `tc.elicit.consumed`          | Caller consumed an elicit token.                        |
| `tc.rate_limit.hit`           | Rate limit refused a call.                              |
| `tc.governor.overflow`        | Response-byte governor truncated or refused output.     |
| `tc.vault.cache_reset`        | `reset_vault_cache` was invoked.                        |
| `tc.server.start`             | Server process started, vaults registered.              |
| `tc.server.shutdown`          | Server process exiting (SIGTERM or natural stop).       |

### Data shape

```jsonc
{
  "vault_id":        "<vault>",
  "tool":            "<name | null>",
  "caller_hash":     "<8char>",
  "scopes_required": ["..."],
  "status":          "ok | denied | error",
  "duration_ms":     <number | null>,
  "elicit_token":    "<jti | null>",
  "idempotency_key": "<key | null>",
  "result_size":     <bytes | null>,
  "overflow_bytes":  <bytes | null>,
  "error":           { "code": "...", "message": "..." } | null,
  "count":           <number | null>     // bulk batches; otherwise null
}
```

Bulk operations emit one event per batch with `count` set. No per-row emission inside hot loops.

### Transport

V1 default: local JSONL spool. MORGIANA tails the file.

```
<cache_dir>/<vault>/morgiana-events.jsonl
```

Daily rotation by date (matches G2.3 D8 trace file layout). **No retention is enforced** — `observability.retention` has only `eventLogDays`; a proposed `morgianaEventsDays` key was never implemented, so the spool grows without bound regardless of any value an operator sets. HTTP push is opt-in:

```yaml
observability:
  morgiana:
    spool: true                                            # default
    httpEndpoint: "https://morgiana.internal/events"       # opt-in
    httpHeaders:
      Authorization: "Bearer ${MORGIANA_TOKEN}"
```

Spool and HTTP push can both be enabled. Either failing fails-soft.

### Failure mode

Spool write failure → log to `event_log`, increment `obsidian_tc_morgiana_emit_dropped_total{reason="spool_write_failed"}`, drop the event. HTTP push failure → log, increment counter with `reason="http_push_failed"`, fall back to spool if both are configured. **Tool execution never blocks on event emission.**

Crash-loss budget: 5 seconds (matches G2.3 D8 JSONL trace flush cadence).

### Schema sharing

The CloudEvents data schema lives in `packages/shared/` as a Zod schema. MORGIANA imports it and validates incoming events. Schema version is the `specversion` field; breaking changes bump it.

## Related local stores

Two pre-existing local stores from earlier gates support observability without being part of the export pipeline:

- **JSONL traces** (G2.3 D8). Full per-call replay corpus with optional field-level redaction. **No retention is enforced** — a proposed `tracesDays` key was never implemented, so trace files grow without bound. Source of the V2 retrieval-training corpus.
- **`event_log` table** (G2.3 D9). SQLite audit table for server-internal events including sweep results and emit-drop counts. Default retention 30 days (`observability.retention.eventLogDays`) — the **only** retention this section enforces. Source of truth for any forensic question that crosses the OTEL/Prometheus/MORGIANA boundary.

## Configuration summary

```yaml
observability:
  otel:
    endpoint: null                      # set to enable OTLP HTTP
    headers: {}
  prometheus:
    enabled: false
    port: 9464
    bind: "127.0.0.1"
  morgiana:
    spool: true
    httpEndpoint: null
    httpHeaders: {}
  retention:
    eventLogDays: 30                     # G2.3 D9 — the ONLY enforced retention (see note above)
```

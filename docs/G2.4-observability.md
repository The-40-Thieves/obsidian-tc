# Observability Model (G2.4)

**Status (THE-598, 2026-07-27):** this is a point-in-time G2 design document (same "design-era" convention used in [`G2.1-tools.md`](G2.1-tools.md) and [`G2.3-storage.md`](G2.3-storage.md)), not a living reference. The child-span hierarchy has since shipped behind `observability.otel.detail` (see "Span model" below); sampling (`traces_sample_rate`) never did and is not in the current schema. Config-key spellings below have been corrected to the shipped camelCase JSON shape (`packages/shared/src/config.schema.ts`); the Prometheus catalog is docgen-generated and stays current. For the always-current, generated field reference use `docs/wiki/Configuration.md` (`BEGIN GENERATED: config`); for the living operator-facing page use [`docs/wiki/Observability.md`](wiki/Observability.md) and [`docs/src/content/docs/observability/otel.md`](src/content/docs/observability/otel.md).

obsidian-tc emits three observability streams: OTEL traces, Prometheus metrics, and MORGIANA CloudEvents. Each is opt-in beyond a sensible local default, and none of them block tool execution if the export path fails.

## Pillars

| Stream            | Purpose                                                       | Default                            |
| ----------------- | ------------------------------------------------------------- | ---------------------------------- |
| OTEL traces       | Per-call structured spans for debugging and latency analysis. | stdout in dev; off in production.  |
| Prometheus metrics | Aggregate counters, histograms, gauges for SLOs and alerting. | Endpoint disabled (`:0`).          |
| MORGIANA events   | Structured CloudEvents for security and ops audit.            | Local JSONL spool, on by default.  |
| JSONL traces      | Full per-call replay corpus (specified in G2.3 D8).           | On by default per vault.           |
| `event_log` table | Local SQLite audit table (specified in G2.3 D9).              | On by default per vault.           |

## OTEL traces

### Span model

One root span per tool call. Span name: `obsidian_tc.<tool_name>`. Span kind: `SERVER`.

`observability.otel.detail` selects how much is emitted under it (default `"root"`):

| `detail`     | Emits                                                                                          |
| ------------ | ---------------------------------------------------------------------------------------------- |
| `"root"`     | The root span only, exactly as before. No child span is created and no attribute is allocated.  |
| `"children"` | Plus one child span per dispatch stage, each parented to the root (table below).               |
| `"verbose"`  | Plus per-item spans for batch tools and SQLite transaction spans, capped per request.          |

Stage spans are sequential siblings under the root, in pipeline order. A stage that a call does not
reach (or a gate that is not configured) has no span:

| Child span         | Covers                                                                                        |
| ------------------ | --------------------------------------------------------------------------------------------- |
| `input_parse`      | Input schema validation                                                                       |
| `auth_check`       | Authentication and required-scope check                                                       |
| `policy_eval`      | Vault binding, per-vault ACL selection, read-only and vault-kind gates, the tool's precheck   |
| `idempotency`      | Idempotency-key claim or replay (keyed calls only)                                            |
| `rate_limit`       | Dispatch rate-limit gate (only when a limiter is configured)                                  |
| `hitl_check`       | Elicit-token verification (HITL-gated calls only)                                             |
| `acl_eval`         | Central folder-ACL enforcement, immediately before the handler                                |
| `tool_impl`        | The tool handler                                                                              |
| `output_serialize` | Output-schema check, serialization, governor byte budget                                      |

`verbose` adds, all nested under the stage that was running (normally `tool_impl`):

| Span                   | Emitted for                                                                      |
| ---------------------- | -------------------------------------------------------------------------------- |
| `batch_item`           | Each item of a byte-paged batch tool (`read_notes`, `read_resources`, `search_and_read`); attribute `obsidian_tc.item_index` |
| `db_transaction`, `db_savepoint`, `db_write_transaction` | SQLite transaction helpers in `db/txn.ts`     |

**Bound.** At most 64 non-root spans per request (`MAX_SPANS_PER_REQUEST`). The pipeline stages
(at most 9) are always emitted; `batch_item` and `db_*` spans share the remaining budget and are
dropped once it is spent. When any were dropped the root span carries `obsidian_tc.spans_dropped`
with the count, so a truncated tree is distinguishable from a small one.

**What never appears on a span.** Child spans carry no attributes on success beyond
`obsidian_tc.item_index`. A failure sets ERROR status on the span of the stage that failed, with the
structured error code (`obsidian_tc.error_code` and the status message) and nothing else: no
exception event, no message, no stack, no argument, path or note content. Every string attribute is
passed through the same credential scanner trace-argument capture uses (`experiential/redact.ts`).

The child-span source is `packages/server/src/otel/dispatch-spans.ts`; dispatch marks stage
boundaries with `spans?.stage("<name>")`, which is a no-op when `detail` is `"root"`.

### Attributes

```
service.name                  = "obsidian-tc"                       # resource attribute
service.version               = <semver>                            # resource attribute
service.instance.id           = <pid + start_ts>                    # resource attribute
obsidian_tc.vault_id          = <vault>
obsidian_tc.tool              = <tool_name>
obsidian_tc.caller_hash       = <sha256(caller_id)[:8]>
obsidian_tc.scopes_required   = <comma-list of scope strings>
obsidian_tc.status            = "ok" | "denied" | "error"
obsidian_tc.error_code        = <code | absent>
obsidian_tc.elicit_used       = bool
obsidian_tc.overflow_b        = <number, 0 if no truncation>
obsidian_tc.duration_ms       = <number>
rate_limit.hit                = bool
```

13 attributes as shipped (3 resource + 10 span, `packages/server/src/otel/attrs.ts`'s `SPAN_ATTR`) — an `obsidian_tc.idem_hit` attribute was proposed here and never implemented; it is not in `attrs.ts` and does not appear on a span.

Caller identity is hashed to 8 hex chars to bound cardinality.

### Sampling — proposed, never shipped

There is no sampling knob in the shipped schema. Every dispatch is traced, unconditionally, whenever tracing is enabled (`observability.otel.endpoint` set); `observability.otel.detail` controls span depth, not how many calls are traced. The subsection below is retained as the original design proposal.

#### Original proposal (not implemented)

`observability.traces_sample_rate: 1.0` was proposed as the V1 default (laptop scale, traces are cheap), with error spans always sampled regardless of rate. None of this was built — see "Sampling" above.

### Export

OTLP HTTP. `observability` is a single **global** block (not per-vault):

```yaml
observability:
  otel:
    endpoint: "http://localhost:4318"   # OTLP HTTP receiver
    headers:
      Authorization: "Bearer ${OTEL_TOKEN}"
    detail: "root"                      # "root" (default) | "children" | "verbose"
```

Default: off (no exporter created) unless `observability.otel.endpoint` is set. MORGIANA can be the configured endpoint.

### Endpoint

Server process exposes `/metrics` on `observability.prometheus.port` (default `9464`, only when `observability.prometheus.enabled` is true — the endpoint is off by default, not merely bound to port 0). Bind localhost only by default; non-localhost bind triggers the same hardcoded JWT requirement as MCP transport (G2.2 commitment 8).

```yaml
observability:
  prometheus:
    enabled: true
    port: 9464
    bind: "127.0.0.1"
```

### Cardinality notes

Caller hash is deliberately omitted from Prometheus labels. Prometheus' cardinality budget is tighter than OTEL's, and caller-dimension breakdowns belong in traces and MORGIANA events. Use scope class instead of full scope strings for the same reason.

## MORGIANA events

### Envelope

CloudEvents 1.0:

```jsonc
{
  "specversion": "1.0",
  "id": "<uuid>",
  "source": "obsidian-tc/<vault_id>",
  "type": "<event_type>",
  "datacontenttype": "application/json",
  "time": "<rfc3339>",
  "data": { ... }
}
```

### Event types

| Type                          | Emission point                                          |
| ----------------------------- | ------------------------------------------------------- |
| `tc.tool.call.completed`      | Every tool call (success or failure).                   |
| `tc.acl.denied`               | Scope or path denial.                                   |
| `tc.elicit.requested`         | Policy layer issued an elicit token.                    |
| `tc.elicit.consumed`          | Caller consumed an elicit token.                        |
| `tc.rate_limit.hit`           | Rate limit refused a call.                              |
| `tc.governor.overflow`        | Response-byte governor truncated or refused output.     |
| `tc.vault.cache_reset`        | `reset_vault_cache` was invoked.                        |
| `tc.server.start`             | Server process started, vaults registered.              |
| `tc.server.shutdown`          | Server process exiting (SIGTERM or natural stop).       |

### Data shape

```jsonc
{
  "vault_id":        "<vault>",
  "tool":            "<name | null>",
  "caller_hash":     "<8char>",
  "scopes_required": ["..."],
  "status":          "ok | denied | error",
  "duration_ms":     <number | null>,
  "elicit_token":    "<jti | null>",
  "idempotency_key": "<key | null>",
  "result_size":     <bytes | null>,
  "overflow_bytes":  <bytes | null>,
  "error":           { "code": "...", "message": "..." } | null,
  "count":           <number | null>     // bulk batches; otherwise null
}
```

Bulk operations emit one event per batch with `count` set. No per-row emission inside hot loops.

### Transport

V1 default: local JSONL spool. MORGIANA tails the file.

```
<cache_dir>/<vault>/morgiana-events-<YYYY-MM-DD>.jsonl
```

Daily rotation by UTC date (matches G2.3 D8 trace file layout). Each event is one `O_APPEND` write to the file for its own day, so a finished day is a file nothing appends to. **Retention** is a `morgiana-spool-sweep` job on the maintenance interval, deleting whole finished day files and never truncating: `observability.retention.spoolRetentionDays` (default 30; `0` keeps the spool forever) drops files older than the window, and the optional `observability.retention.spoolMaxBytes` caps each vault directory by deleting its oldest day files first. The file for the current UTC day, any file modified in the last hour (the midnight boundary), symlinks and anything not named like a spool file are never touched. Each sweep logs one `[maintenance] morgiana spool sweep` line and adds to `obsidian_tc_morgiana_spool_files_pruned_total{reason}`. Set the window longer than MORGIANA's worst-case downtime, since a deleted day is gone. HTTP push is opt-in:

```yaml
observability:
  morgiana:
    spool: true                                            # default
    httpEndpoint: "https://morgiana.internal/events"       # opt-in
    httpHeaders:
      Authorization: "Bearer ${MORGIANA_TOKEN}"
```

Spool and HTTP push can both be enabled. Either failing fails-soft.

### Failure mode

Spool write failure → log to `event_log`, increment `obsidian_tc_morgiana_emit_dropped_total{reason="spool_write_failed"}`, drop the event. HTTP push failure → log, increment counter with `reason="http_push_failed"`, fall back to spool if both are configured. **Tool execution never blocks on event emission.**

Crash-loss budget: 5 seconds (matches G2.3 D8 JSONL trace flush cadence).

### Schema sharing

The CloudEvents data schema lives in `packages/shared/` as a Zod schema. MORGIANA imports it and validates incoming events. Schema version is the `specversion` field; breaking changes bump it.

## Related local stores

Two pre-existing local stores from earlier gates support observability without being part of the export pipeline:

- **JSONL traces** (G2.3 D8). Full per-call replay corpus with optional field-level redaction. **No retention is enforced** — a proposed `tracesDays` key was never implemented, so trace files grow without bound. Source of the V2 retrieval-training corpus.
- **`event_log` table** (G2.3 D9). SQLite audit table for server-internal events including sweep results and emit-drop counts. Default retention 30 days (`observability.retention.eventLogDays`); the MORGIANA spool has its own bounds (see above). Source of truth for any forensic question that crosses the OTEL/Prometheus/MORGIANA boundary.

## Configuration summary

```yaml
observability:
  otel:
    endpoint: null                      # set to enable OTLP HTTP
    headers: {}
  prometheus:
    enabled: false
    port: 9464
    bind: "127.0.0.1"
  morgiana:
    spool: true
    httpEndpoint: null
    httpHeaders: {}
  retention:
    eventLogDays: 30                     # G2.3 D9
    spoolRetentionDays: 30               # morgiana spool day files; 0 = keep forever
    # spoolMaxBytes: 1073741824          # optional per-vault size cap on the spool
```
